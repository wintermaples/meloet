# バグ報告

コード（`crates/` と `ui/`）を掃除して見つけたものです。バグ、UI/UX の問題、片方にあって対になるものにはないもの（対等性のずれ）を含みます。

- 見つけた一件ごとに一つのファイルを [`reports/`](../reports/) に置きます。すべて [`TEMPLATE.md`](../TEMPLATE.md) の形です。
- 報告は `python3 -I tools/bugs/report.py new --area <AREA> --kind bug|ui-ux|parity --severity high|medium|low --title "<one line>"` で作り、そのあとで項目を埋めます。テンプレートを手でコピーしないでください。
- `python3 -I tools/bugs/report.py index` は、すべての報告を確かめ、[`INDEX.md`](../INDEX.md) を書きます。
- `python3 -I tools/bugs/html.py` は [`report.html`](../report.html) を書きます。すべての報告と「後で」の行を一つのページにまとめ、ブラウザで読めます(検索、重大度・種類・領域での絞り込み。`report.html#<ID>` で一件の報告が開きます)。報告を変えたら、もう一度実行してください。
- バグではないが後で見たい点(遅さ、仕様とモックの食い違い、設計上の心配)は [`later/`](../later/) に入れます。領域ごとに一ファイル、一点につき一行です。掃除では直しません。

## 項目

- `kind`: `bug`（動作が間違っている）、`ui-ux`（動きはするが、使う人が迷う、止まる、または誤解する）、`parity`（片方にあり、対になるものにはない。似た画面の部品、Rust と画面、日本語と英語の文面）。
- `severity`: `high`（データが失われる、または壊れる、音が止まる、または間違う、クラッシュ、固まる、使えない部品）、`medium`（使う人が普通に使う中で出会う間違った動作。回り道はある）、`low`（まれな場面、小さな見た目や文面の不具合）。
- `status`: `reported`（見つかった。まだ確かめていない）→ `confirmed`（検証者が本当だと確かめた）→ `fixed`（直した）。`needs-lead`: 本当の問題だが、直すにはリードの決めることが必要。誤りと分かった報告は削除します。
