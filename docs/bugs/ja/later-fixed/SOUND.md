# SOUND — 2 回目で直した点 (2026-11-25)

- crates/meloet-sound/src/synth/poly.rs:535 — 押さえている音の `filter_env` は、32 フレームのまとまりごとに掛けられ、下限がありません。ベース、リード、パッドなどの音を 11〜90 秒押さえ続けると、非正規化数（denormal）の値になります。まとまりごと、ボイスごとに一回の演算なのでコストは小さく、問題になるのは、ループの中で小さな値を 0 にする規則に関わる点だけです。
- crates/meloet-sound/src/sampler/player.rs:476-482, 223-227 — パックの領域の半音数に上限がありません（SF2 の形だけが制限されています）。`instrument.json` は `pitchKeytrack` を ±1200 % まで許します。そのため `root` から遠い鍵では `step` が大きくなりすぎ、オーディオスレッドの `mix` にある `last + 3` がオーバーフローします（デバッグではパニック、リリースでは誤った高速経路に入り、そこでスライスの添字がパニックします）。パックは `tools/sounds/build.py` で作るため、今は届きません。`MAX_SHAPED_SEMITONES` のようなクランプを全領域に付ければ塞げます。
- crates/meloet-sound/src/sampler/player.rs:35, 709-714 — `MAX_SHAPED_SEMITONES` のコメントは、形を付けた音が元ファイルから 120 半音より離れないと書いています。しかし、モジュレーションのエンベロープ、ビブラート、LFO のセント（それぞれ ±12 000 に制限）が、ブロックごとにその上に足されるため、最大 ±360 半音までずれます。64 ビットではクラッシュしません。コメントか制限のどちらかを合わせられます。
- crates/meloet-sound/src/sf2/zones.rs:261-311 — 作業量の上限は、作られたゾーンの数だけです。壊れたプリセットで、ローカルゾーンが最大 16 384 個あり、その各インストゥルメントが最大 16 384 個のゾーンを持ち、それらがすべて失敗する（サンプルが範囲外、鍵の重なりなし）場合、約 2.7e8 回ループし、プリセットのゾーンごとに 16 384 個のゾーンの `Vec` を作ります。SF2 の読み込み（および `keys`、`key_names`）は、そのスレッドで数分かかることがあります。
- crates/meloet-sound/src/sf2/mod.rs:160-169 — `Sf2File::keys` は `key_lo.min(127)` を取るため、鍵の範囲がすべて 127 より上にあるゾーン（壊れたファイル）は、鍵 127 に印を付けます。また、`spec` が捨てるはずのゾーン（ROM サンプル、不正なレート、範囲外のサンプル）も数えます。`key_names` は `key_lo > 127` を飛ばしますが、弾けないゾーンは飛ばしません。
- docs/architecture.md 25-23 (last line) — `Gate::gain` と `DeEsser::cut_db` を、読み出せるかのように書いています。`crates/meloet-sound/src/effects/gate.rs` と `de_esser.rs` では、これらは非公開のフィールドで、読み出す手段がありません。
