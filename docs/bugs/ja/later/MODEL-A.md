# MODEL-A — 後で見たい点(バグではない)

- crates/meloet-model/src/quantize.rs:81-88 — 「始まりだけ」では、元の位置の番号を持つ音符は、その元の音符の長さを取ります。そのため、最初のクオンタイズのあとで手で変えた長さが、「かけなおす」で録音時の長さに戻ります。architecture 16 は「長さを保つ」と「録音した位置から始まる」と書いていますが、どの長さのことかは書いていません。
- crates/meloet-model/src/timeline.rs:85-90 — テンポの点は、その次の点を消したあとも `ramp: true` のままになります(最後にある間は害がありません)。あとで次の点を足すと、使う人が頼んでいないのに、新しい点へ向かって変わり始めます。
- crates/meloet-model/src/record.rs:136-140 — 終わった回に遅れて届いた鍵は、その時刻のままなので、いま進んでいる回の終わりから一周分ずれた場所に入ります(`closed_passes_are_given_once_and_late_keys_go_on` で意図どおりとしてテストされています)。音楽的には疑問があります。
- crates/meloet-model/src/quantize.rs:146-174 — 「もとの位置へ戻す」は、`count: 0` の手を作ることがあります。それは元の位置を消すだけです(手で動かしたあとで全部の音符がすでに戻っているとき、または元の位置の番号を持つすべての音符が消えたときに起こります)。
- crates/meloet-model/src/arrange.rs:565-591 — つなぐとき、それぞれのクリップの中にある CC の点だけが残ります。そのため、`track_events` でクリップの始まりまで持ち越したペダルやベンド(またはクリップの終わりでリセットされたもの)が、つないだあとには違う音になります(architecture 24-6 に書かれている通りです)。
