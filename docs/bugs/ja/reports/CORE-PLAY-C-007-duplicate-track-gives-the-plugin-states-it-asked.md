# CORE-PLAY-C-007: トラックの複製で、頼んだプラグインの状態を、プラグインではなくスロット番号でコピーに渡してしまう

## Where

crates/meloet-core/src/play/plugs/copies.rs:54-72 (`ask_copy_states` は、キーを一度確認したあと、場所だけを残す)
crates/meloet-core/src/play/plugs/copies.rs:106-132 (`copy_state_said` は `(place, state)` を返し、状態が属するキーは残さない)
crates/meloet-core/src/play/tracks.rs:109-122 (`make_copy` は、各状態を、コピーのその場所に今あるプラグインに、そのプラグインのキーで置く)

## What happens

プラグインが鳴っているトラックで「トラックを複製」を使うと、まず各プラグインに状態を頼み、全員が答えたらコピーを作ります(12 版の A3)。答えは場所だけでコピーに対応づけられます(音源、またはインサートのスロット番号)。頼んだあと、最後の答えが来るまでの間に、トラックのインサートの順番が入れかえられた(`MoveInsert`)、またはインサートが別のプラグインに入れかえられた(`ReplaceEffect`、「入れかえる」)場合、プラグイン A の状態が、今そのスロットにあるプラグイン B に渡されます。その呼び出しは `set_plugin_state(doc, at, &key_of_B, state_of_A, ..)` です。コピーの B は A のバイト列を持つことになり、それが曲(保存時はファイル)に書かれます。読みこむと、B は自分のものではない状態を受け取り、プラグインホストはそれを拒否する(そのスロットは空のまま。`plugin_unreadable` → `Failed`)か、B がそれを別のものとして読みます。

## What should happen

copies.rs の doc コメントには「コピーのプラグインは、曲がそのプラグインに持っている状態を受け取る」とあります。つまり、同じプラグインの状態です。プラグインの状態は、そのキーに属します(docs/architecture.md 20-5: 「パラメーターと状態は形式ごとに違う」、24-16 G: 「一つのプラグインの二つの形式は、互いの状態を受け取れない」)。`ask_copy_states` は頼むときに `q.key == p.plugin.key` を確認しています。答えも同じ確認を受けるべきです。

## How to trigger

コードを読んで確認したもので、実行はしていません。
1. 二つの違うプラグインのエフェクト、Zam(スロット 1)と LSP(スロット 2)、がどちらも鳴っているトラック。
2. 「トラックを複製」: 二つの `StateAsk::Copy` の依頼が出る。答えは、プラグインホストの一つのスレッドを通って後から届く(たとえば別のプラグインの遅い `Load` の後ろ、または、プロセスのメインスレッドでプラグインのウィンドウを作っているところ。10〜300 ms)。
3. 答えが届く前に、ミキサーで LSP を Zam の上にドラッグする(`MoveInsert`)。両方が AI のまとめ(state/ai.rs の `ai_hold`)の後ろで保留されていた場合も、意図は続けて処理される: 複製、順番の入れかえ、それから答え。
4. コピーは今の曲から作られる。そのスロット 1 は LSP で、Zam の状態を LSP のキーで受け取る。

## Cause

`CopyAsk` は `place` と `puts` を持ちますが、プラグインのキーは持ちません。`copy_state_said` と `make_copy` は、元のトラックのその場所に今あるプラグインが、頼まれたものかどうかを確認しません。`forget_copy` は、別の曲に切りかえたときや履歴をさかのぼったときにしか呼ばれないため、頼んだあとの他の操作(並べ替えや入れかえ)では気づきません。

## Suggested fix

`CopyAsk` / `CopyStates` にキー(またはチケット)を残し、`make_copy` では、コピーのその場所のプラグインが同じキーを持つ場合にだけ状態を与えます(より良いのは、チケットを使って今の場所を探し、動かされたプラグインも自分の状態を受け取れるようにすることです)。その場所にプラグインがない状態は捨て、コピーは曲の状態を保ちます。プロトコルやファイルは変えません。

## Verification

コードを読んで確認しました(テストは実行していません)。`ask_copy_states`(`play/plugs/copies.rs:46-90`)は、頼むときにキーを一度確認し、`ticket`、`place`、`puts` だけを残します。`copy_state_said` は `(place, state)` を返し、`make_copy`(`play/tracks.rs:109-122`)は、各状態を、コピーのその場所に今あるプラグインに、そのプラグインのキーで置きます。`forget_copy` は、別の曲のときや履歴をさかのぼったときにしか動かないため、頼んだあとから最後の答えまでの間にある、元のトラックの `MoveInsert` や入れかえは検出されません。重大度 `low` は変えません(二つの意図が、答えを待つ数十〜数百ミリ秒の間に入る必要があるため)。

訂正: なし。

修正案: `crates/meloet-core/src/play/plugs/copies.rs`: `CopyAsk` に頼んだプラグインのキーを残し、答えと一緒に返す(`CopyStates` の行は `(place, key, state)`)。`crates/meloet-core/src/play/tracks.rs` の `make_copy`: コピーのその場所のプラグインが同じキーを持つ場合にだけ状態を与え、そうでなければ曲の状態のままにする。(動かされたプラグインをチケットで追いかけるのは、修正に必要な範囲を超えます。)テスト: コピーのテストで、頼んだあと、`MoveInsert`、答えが届く、という流れ。どの状態も、もう一方のプラグインに入らないこと。

## Fix

`crates/meloet-core/src/play/plugs/copies.rs`: `CopyAsk` は頼んだプラグインのキーを持ちます。最後の答えが来たとき、状態は、そのチケットのプラグインが頼んだ場所に今もあり、その場所の曲のプラグインが同じキーを持つ場合にだけ残されます。それ以外の状態は捨てられ、コピーはそこで曲の状態を保ちます。`play/tracks.rs`(`make_copy`)は変えていません。

テスト: `play::plugs::tests::a_copy_gets_a_state_only_where_the_plugin_that_said_it_is`(頼んだあと、`MoveInsert`、答えが届く)。
