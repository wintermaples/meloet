# SOUND-001: エレクトロ・キットのエンベロープが非正規化数まで減衰し、その音の残りの間ずっとそのまま残る

## Where

crates/meloet-sound/src/synth/kit.rs:271-276 (`Voice::tick`: `env[0..3] *= coef[..]`。フラッシュ処理がない)
crates/meloet-sound/src/synth/kit.rs:439 (`render`: 音は `env[0] + env[1] < SILENT` になったときだけ終わる)
crates/meloet-sound/src/synth/kit.rs:125, 141, 180-185 (短いサブエンベロープ: クリック `ring(0.0015)`、ピッチ `dc(0.030)` / `dc(0.012)`、シンバルの打ちの部分 `ring(0.06)` / `ring(0.025)`)

## What happens

オーディオスレッドで、エレクトロ・キットのサンプルごとのループの中で、一打のうちのいくつかのサブエンベロープ (キックとタムのクリック、キック、タム、スネアのピッチの下降、クラッシュとライドの打ちの部分) は、聞こえる値よりずっと小さくなった後も、減衰係数を掛けられ続けます。それらは最小の正規化 f32 (1.18e-38) を下回り、非正規化数のまま 0 にならずに止まります。`x * coef` の結果が `x` から半ステップ未満しか離れていないと、丸めで `x` に戻ってしまうためです。numpy の f32 で 48 kHz の場合を計算して確認しました (meloet では実行していません)。

| サブエンベロープ | coef | 非正規化になる時刻 | 止まる値 |
|---|---|---|---|
| キック / タムのクリック、`ring(0.0015)` | 0.98621 | 0.13 s | 5e-44 |
| スネアのピッチ、`dc(0.012)` | 0.99827 | 1.05 s | 4.0e-43 |
| キックのピッチ、`dc(0.030)` | 0.99931 | 2.62 s | 1.0e-42 |
| ライドの打ち、`ring(0.025)` | 0.99917 | 2.18 s | 8.4e-43 |
| クラッシュの打ち、`ring(0.06)` | 0.99965 | 5.24 s | 2.0e-42 |

音そのものは続きます。音が終わるのは `env[0] + env[1] < 1e-4` のときだけで、`env[0]` の方が長く響くためです。キックは 1.84 s、タムは 1.5〜2.0 s、スネア (ベロシティ 127) は 1.29 s、ライドは 5.1 s、クラッシュ (ベロシティ 127) は 9.2 s まで響きます。「のび」が 100 % のときは、どれも 4 倍長くなります。そのため、0.13 s を過ぎて響くキックごと (テンポ 0.5 s の拍では、拍ごとの 0.37 s)、5.2 s を過ぎて響くクラッシュごと、2.2 s を過ぎて響くライドの打ちごとに、サンプルごとに非正規化数の上での演算が何回か行われます (`env[k] *= coef[k]` のあとに `rng.bipolar() * env[1] * click` や `hit * env[1]`)。非正規化数で遅くなる CPU では、それぞれが数十から数百サイクルかかることがあります。

## What should happen

CLAUDE.md の規則: 「信号を足すところでは NaN を止め、ループの中では小さい非正規化数を 0 にする (FTZ や DAZ は設定しない)。」 docs/architecture.md 19-2: 「各エフェクトと音源は、非正規化数を自分で防ぐ (フィードバックとフィルタの状態で 1e-18 未満の値は 0 にし、エンベロープは −80 dB で止める)。」 同じ仲間の音源はこれを行っています。サンプラーはすべてのエンベロープを `SILENT` で終わらせ (`sampler/player.rs:176, 181, 190`)、SF2 のフィルタは `TINY` で 0 にし (`sampler/shape.rs:339`)、エフェクトは `dsp::flush` を呼びます。

## How to trigger

コードを読んで確認しました。実行はしていません。エレクトロ・キットをトラックに置き、キック (鍵 36) かクラッシュ (鍵 49) を 1 回弾いて鳴らし続けます。キックの 0.13 s あと (クラッシュの 5.2 s あと) から、その音が終わるまで、サンプルごとにその音の値はすべて非正規化数の上で計算されます。フレーズの頭ごとにクラッシュがある曲や、拍ごとにキックがある曲では、これが常に起きています。

## Cause

`Voice::tick` は 3 つのエンベロープを毎サンプル掛けますが、小さい値を 0 にすることは一度もありません (kit.rs:271-276)。音が終わるかどうかは `env[0] + env[1]` だけで決まる (kit.rs:439) ため、短いサブエンベロープ (キックの `env[1]`、キックとスネアの `env[2]`、クラッシュとライドの `env[1]`) は、音が聞こえなくなった後もずっと減衰し続けます。テスト `denormals_stay_finite_and_small` はエフェクトだけを対象としていて、キットは見ていません。

## Suggested fix

`Voice::tick` で、3 回の掛け算の後、1e-18 未満の各 `env[k]` を 0 にします。エフェクトが使っている `flush` (`crate::effects::dsp::flush`) を使うか、同じ働きのローカルの関数 (2 行) を使います。見た目、文言、プロトコル、ファイルの形は変えません。音が変わるのは、1 サンプルの中で 1e-38 よりずっと小さい値の分だけです。ただし、組み込みの 31 音をハッシュで比べる内蔵音のつまみのテスト (アーキテクチャ 25-27) の保存済みのハッシュは、そのような小さい値が入っていなかったかを見る必要があるかもしれません。

## Verification

コードを読んだうえで、私が実行した計算で確認しました (python と numpy の float32。48 kHz で `Voice::tick` と同じ掛け算)。クリックのエンベロープ (`ring(0.0015)`、coef 0.9862071) は 0.131 s から非正規化数になり、5e-44 で止まります。キックのピッチのエンベロープ (`dc(0.030)`、coef 0.9993058) は 2.62 s から非正規化数になり、1.009e-42 で止まります。これらは報告の表と一致します。`Voice::tick` (`kit.rs:271-276`) にはフラッシュ処理がなく、音は `env[0] + env[1] < SILENT` (`kit.rs:439`) になったときだけ終わるため、`env[0]` が響いている間は短いエンベロープは非正規化数のままです。meloet 内での CPU の負荷は測っていません。問題は書かれた規則 (CLAUDE.md: 「ループの中では小さい非正規化数を 0 にする」。アーキテクチャ 19-2) に反することで、負荷の大きさは CPU によります。重大度 `low` はそのままです。

Corrections: 訂正なし。

修正の計画: `crates/meloet-sound/src/synth/kit.rs` の `Voice::tick` で、掛け算の後に 1e-18 未満の `env[k]` を 0 にする。`synth` から `crate::effects::dsp` のフラッシュに届くならそれを使い、届かなければ 2 行のローカルの関数を使う。キットを非正規化数のテストに加える (`denormals_stay_finite_and_small` か、キットのテストの隣に新しいテスト。キックの 3 s の後、`env[1]` と `env[2]` がちょうど 0 になっている)。変更の後、内蔵音のハッシュのテストを実行する。保存済みのハッシュは、キットが変わり、その差が 1e-18 未満だと確認できたときにだけ更新する。

## Fix

- `crates/meloet-sound/src/synth/kit.rs` の `Voice::tick`: 掛け算の後、1e-18 未満の各エンベロープを 0 にする (`effects::dsp::flush`)。
- テスト: `synth::kit::tests::no_envelope_rings_on_below_hearing` (12 種類すべての音をベロシティ 127 で 10 s 鳴らし、響いている声のエンベロープはすべて 0 か、少なくとも 1e-18 であることを確認する)。保存済みのハッシュは変えていない (`tests/knobs.rs` とキットの他のテストは元のまま通る)。
