# UI-ARRANGE-002: 小節線の上にないループ範囲が最も近い小節線に描かれ、数字が状態行と違う

## Where

ui/src/components/arrangeGeom.ts:296-302 (`loopBars`: 両端を最も近い小節線にそろえる)
ui/src/components/Arrange.svelte:370 (`loopBars` から作る `songLoop`)
ui/src/components/Arrange.svelte:380 (`loopX`), 572-578 (クリップ欄の上のループ線), 1722-1724 (「マーカー ・ ループ 6–7」), 1770-1772 (目盛の上のループの強調の印)

(ピアノロールも同じことをしている: ui/src/components/pianoroll/Roll.svelte:1015)

## What happens

アレンジは「最も近い」でループ範囲を小節線の番号に変え、その番号からループの印、クリップの上の二本のループ線、見出しの「マーカー ・ ループ a–b」を描く。ループ範囲が小節線の上にないと、これらはすべて最も近い小節線に置かれ、ループが実際に戻る場所に合わない。状態行の「ループ a–b」は Rust から来ており、こちらは外側へ丸めるので、同じループに対して二つの文字が違う数字を示す。

小節線の上にないループは簡単に作れる。「ここから次のマーカーまでをループに」は二つのマーカーのティックをそのまま使い、マーカーは拍にそろう(再生の線での K、マーカーの行でのダブルクリック、マーカーのドラッグ)。拍子の変更を前に入れたときにも起きる。ループはそのティックを保ち(architecture 21-2)、小節線が動くからである。

作業例(4/4 拍子、コードから読んだ内容): マーカーが 5.3.0000 と 7.2.0000 にあり、「ここから次のマーカーまでをループに」を実行する。ループは小節線 5.5 から小節線 7.25 まで再生される。アレンジは小節線 6 から 7 まで描き、「ループ 6–7」と言う(5.5 は同点なので後の線、7.25 は 7 になる)。状態行は「ループ 5–8」と言う。描かれた印の端をつかんで動かすと、離したときに反対側の端も丸めた小節線へ動く(丸めた `fixed` の小節で `setLoop`)。

## What should happen

描かれるものはループが戻る場所であり、二つの文字は一致するべきである。仕様書 3 (目盛の規則): 「ループ範囲は小節の単位のまま」。仕様書 3 (Y18) は「ここから次のマーカーまでをループに」を提供する。どちらかを選ぶ: マーカーから作る範囲を小節の単位にそろえる(そうすれば描き方は正しい)か、画面はその範囲を実際のティックで描き、数字は Rust の `bars` と同じ規則で作る。

## How to trigger

コードから読んだもので、実行はしていない。小節 5 の中の場所で止まって K を押し、小節 7 の中の場所へ動いて K を押し、最初のマーカーを右クリックして「ここから次のマーカーまでをループに」を選び、Space を押す。ループはマーカーで戻るが、ループの印と線は最も近い小節線にあり、見出しと状態行は違う数字を示す。

## Cause

`loopBars` は両端をそれぞれ最も近い小節線に丸める (`lineNear`)。一方 `loop_from_marker` (と前にあった拍子の変更) は小節線の上にない範囲を作り、Rust の `bars` は外側へ丸める。同じ `TickRange` を三通りに読んでいる。

## Suggested fix

リードの判断が必要: (a) `loop_from_marker` が範囲を小節の単位にそろえる(開始の小節の頭と、終わり以後の小節線まで。仕様書 3 はループ範囲が小節の単位のままだと言う)、または (b) ティックは保ち、画面がループの印と線を `loopRange.start` / `loopRange.end` に描き、見出しの数字は `Play::bars` と同じ規則で作る。どちらも、プロトコルや文面は変えない。

## Verification

コードを読んで確認したもので、実行はしていない。`loopBars` (`arrangeGeom.ts:296-302`) は両端を最も近い小節線に丸め、`loop_from_marker` (`play/timeline.rs:464-480`) はマーカーのティックを保ち、Rust の `bars` (`play.rs:757-766`) は外側へ丸める。作業例は正しい(5.5 は同点の規則で小節線 6、7.25 は 7。Rust は 5–8 と言う)。

どちらの側に従うかは文書が決めているので、`needs-lead` ではない:
- architecture 21-2: 拍子の変更を前に足したとき「ノート、クリップ、オートメーションの点、マーカー、テンポの点、ループ範囲は**ティックを保つ**」。つまり `loop_from_marker` が何をしても、小節線の上にないループ範囲は存在し、画面はそれを正しく描く必要がある。
- 仕様書 3 (Y18): 「ここから次のマーカーまでをループに」は「(最後のマーカーなら曲の終わりまで)」であり、マーカーは小節ではなく拍にそろう。範囲はマーカーで終わることを意図している。Rust の `bars` の doc コメント(「範囲が触れる小節 … その最初の小節と、終わりにある、またはその後の小節線」)は、Rust がすでにそのような範囲を想定していることを示す。
- 仕様書 3 の 52 行目・92 行目 (「目盛をドラッグすると小節の単位でループ範囲を決める」「ループ範囲は小節の単位のまま」) は目盛のドラッグが作るものについてであり、目盛のドラッグは今も小節の単位を作る。

よって案 (b): Rust はそのままにし、画面を変える。

Fix plan: `ui/src/components/arrangeGeom.ts` で、ループに二つの読み方を与える: 描く場所(`range.start` / `range.end` をティックのまま)と、見出しの数字(`Play::bars` の規則で、開始を含む小節と、終わり以後の小節線。画面のテンポマップに必要なものがある)。`ui/src/components/Arrange.svelte` では `loopX`、二本のループ線、強調の印 (370, 380, 572-578, 1770-1772) にティックを使い、「マーカー ・ ループ a–b」 (1722-1724) は外側の数字を使う。`ui/src/components/pianoroll/Roll.svelte:1015` も同じにする。`startRulerDrag` (1267): 終わりをつかんだとき、残る方の端はそのティックを保つ。`SetLoop` は小節線を受け取るので、`crates/meloet-protocol` で残る端をそのまま送れるか確かめる。送れなければ、残る端は離したときに最も近い小節線ではなく外側の小節線へ動く(修正でそう言う)。`ui/tests/arrange.test.ts` にケースを足す(4/4 でループ 5.3–7.2: ティックで描かれ、見出しは 5–8)。プロトコルや文面の変更は見込まない。

## Fix

画面だけを変えた(Rust はそのまま)。`ui/src/components/arrangeGeom.ts`: `loopBars` は `LoopRange` を返すようになった。数字は core の `Play::bars` の規則(開始を含む小節と、終わりにある、またはその後の小節線)、ティックの `start` / `end` はそのまま。`barLoop` は目盛のドラッグの小節線をそのティックつきで返す。`startRulerDrag` は、つかんだ位置を描かれたティックで測り、残る方の端は外側の小節線の番号になる(`SetLoop` は小節線を受け取るので、小節線の上にない範囲は、一方の端をドラッグしたとき外側へ小節の単位になる)。`ui/src/components/Arrange.svelte`: 目盛の上のループの印と、クリップの上の二本のループ線はティックで描く。「マーカー ・ ループ a–b」は外側の数字を使う(状態行と同じ)。`ui/src/components/pianoroll/Roll.svelte` (3 行: `shownLoop`, `loopX`, ループの印): ピアノロールの目盛もティックで描く。
テスト: `ui/tests/arrange.geom.test.ts` の「a loop range off the bar lines (markers 5.3 and 7.2 in 4/4) …」(新規。既存の「loop range (ticks) → bar line numbers」は `start` / `end` も期待するように変えた)、`ui/tests/arrange.test.ts` の「a loop range off the bar lines (5.3–7.2): the mark at its ticks, 「ループ 5–8」 …」。
