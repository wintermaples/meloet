# Later: CORE-AUDIO

- crates/meloet-core/src/vocalrec.rs:157-161 — after a `write_all` of a voice file fails part way (no space), the next blocks are still written; if space comes back, the bytes after the short write are out of step with the frames (24-bit: noise), and `frames` counts less than the file holds. The recording is stopped soon after (`VocalsCannotGoOn`), so it is a short stretch.
- crates/meloet-core/src/audiofiles/keeper.rs:620-637 — when the decoded copy is made but the peaks file cannot be written, `finish` returns an error and `Done { ok: false }` turns the source to `Missing`: the clip is shown as not found although it plays.
- crates/meloet-core/src/readahead.rs:358-371 (with service.rs:1852-1874) — a narrow race: a file can become ready between a failed `store.open` and `unopened.fetch_or`; `follow_store` then sees no unopened seat and the clip stays silent until the song or the store changes again.
- crates/meloet-core/src/audiofiles/wav.rs:331-353 — `CacheWav::finish` is not synced; after a power loss a renamed but short decoded copy still opens at the right rate, so `playable` calls it ready and the clip's end plays as silence until the cache is emptied.
- crates/meloet-core/src/audiofiles/keeper.rs:538-546 — when `Resample::new` fails after `CacheWav::create`, the `.part` file is left in the cache (the early `?` drops the writer without `abandon`).
- crates/meloet-core/src/audiofiles.rs:429-433 — two table entries with one uid (the same bytes brought in under two names) open only the first name; when that file is missing the other is not tried, and `watch` reports the uid by the first name only.
- crates/meloet-core/src/audiofiles.rs:482-491 — a save cut short while copying leaves `<name>.part` in the person's `音/` folder, which meloet never cleans.
- crates/meloet-core/src/audiofiles.rs:308 — `bring_in` gives the copy its name with `fs::rename`, which replaces a file that got the same name between `find` and the rename; `put_in_place` uses `hard_link` to refuse that.
- crates/meloet-core/src/readahead.rs:325-340 — a second splice that comes inside the 10 ms of the first starts from the first's new audio, so the frame before it (still part old) steps to the new audio without the overlap.
- crates/meloet-core/src/vocalrec.rs:1000-1013 (service/input.rs:413) — `DiskWriter::mark` makes the core thread wait up to 300 ms (`MARK_WAIT`) when no block after `from` has come yet (R while playing with a large output delay and a fast tempo).
- crates/meloet-core/src/audiofiles/keeper.rs:465-467 — a flac whose head says more frames than it holds gets its peaks made again at every start (the peaks file's count never equals `source.frames`).
