## A-2. 仕様書の文の読みかた

| 所 | 読みかた |
|---|---|
| 6 章の文の中の例の値（「鍵盤 49」「ヘッドホン」「1024」「256」「53」「13.5」「1」「7」など） | 本物の値をうめこむ穴にした。まわりの文は一字も変えていない（テストで、穴に仕様書の例の値を入れると仕様書の文と一致することを見はっている） |
| 「窓の高さが 960 以上ならいつも 52」 | 100 % のときの px で比べる（150 % なら CSS の 1440 以上） |
| 「窓のいちばん小さい大きさは、100 % のときの px で 853×533」 | 上と同じ読み。窓の大きさは 853×533 に拡大率をかけた大きさ（切り上げ。100 % 853×533、125 % 1067×667、150 % 1280×800） |
| 音割れの印「rec の 2px」 | 部品の中の小さな寸法として、率をかけて四捨五入（2 / 3 / 3） |
| 「入力計の右はしの案内の文は、2 文目から先に引っこめる」 | うしろの文から 1 つずつ引っこめ、1 文目は残す。それでも入らなければ「…」 |
| 「最後に弾いた鍵盤」 | 鍵を押したとき（NoteOn）だけ数える。ペダルやホイールでは変わらない。弾く前は最後にさした鍵盤 |
| 「同じ装置の中で PC が切りかえる穴」と「PC の設定で止まっている出口」 | ノードがあり、PC がそのデバイスで別の穴を使っている → 前者。ノードがない → 後者（同じデバイスにノードのある穴があっても） |
| えらべない出口の見出しの右「PC が切りかえる物 1 ・ PC の設定で止まっている物 7」 | 数は本物をうめる。0 の種類も 0 として出す |

## A-3. 仕様書にもモックにもない細かい所で、作る側で決めた事

| 所 | 決めた事 |
|---|---|
| スクロールの棒 | つまみのいちばん短い長さは棒の幅（8）。幅 8 は左の線 1px を含む。つまみの外を押すと 1 画面ぶん動く |
| 出口えらびが窓に入りきらないとき | 下のあきもダイアログと同じ 24。窓が低いと上へ寄せる |
| 「いまは使えない出口」のたたみ | 画面の中だけで覚える。ひらくたびに、たたんだ形から始まる |
| 同じ名前の出口 | えらべる出口の中だけでくらべ、言いかえの欄に装置の名前を出す。装置の名前がわからないときは言いかえのまま |
| 鍵盤が 2 台以上 | 名前の欄を広げる「8 文字をこえたら」は「名前 +N」で数える。マウスで出す全部の名前は「 ・ 」でつなぐ。状態行の「入口:」は 1 台の名前だけ |
| 幅が偶数の黒鍵（125 % と 150 % の細い鍵） | 線のまん中に置けないので、あまりの 1 画素を右に置く |
| ピアノロールとミキサーが両方入る窓（944〜959） | 余り（15 px まで）はピアノロールへ。ミキサーは 516 |
| 下の帯が 1 つで入らないとき | 高さのいちばん下は、帯の道具の列の 32 |
