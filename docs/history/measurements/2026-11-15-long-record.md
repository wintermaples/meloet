# 10 分録りつづける（本物のアプリ、release、画面あり）（2026-11-15）

- 道具: `tools/measure/long-record.sh --seconds 600 --no-build`（`CARGO_TARGET_DIR=target/hard-h4`）。窓 1920×1080、出口はアナログヘッドフォン（覚えた設定なしで始め、`chooserConfirm`）、バッファ 256（固定 256）、48000 Hz。
  - 鍵: `crates/meloet-core/tests/vkeys_long_play.rs`（`#[ignore]` の、仮想の鍵盤を弾くだけの物）。600 秒で 2106 音（1 秒に約 3.5 音、80〜400 ms 押す、重なりあり、ベロシティ 20〜30）、ペダル 110 回（9〜13 秒ごとに 3 秒踏む）、ベンド 494 回（13〜18 秒ごとに 0.6 秒の山）。毎回同じ並び。アプリは `MELOET_ONLY_VIRTUAL=1` と `MELOET_VKEYS_NAME` でこの鍵盤だけを受ける。
  - アプリ: `MELOET_COMMANDS` で、出口を決める → メトロノームをオン → 録音（カウントイン 1 小節）→ 鍵が終わってから止める → メトロノームをオフ → 頭へ → 20 秒再生 → 止める → ピアノロールの帯をひらいて、`MELOET_SNAPSHOT` で撮る。
  - 見はり（`tools/measure/long_record_watch.py`）: 1 秒ごとに `pw-top -b` の ERR（meloet のストリームと ALSA の出口）、JavaScriptCore の GC の助手のスレッド（`HeapHelper`）の CPU 時間。10 秒ごとに meloet と WebKitWebProcess の RSS。
  - 再生の音: 20 秒の再生の間、出口のモニターを `pw-record` で録り、1 秒ごとの RMS を出した（`tools/measure/long_record_summary.py`）。
- 3 回まわした。1 回目は GC の数えかたにまちがいがあった（終わったスレッドの分が引かれていた）ので、道具を直して 2 回目と 3 回目をまわした。RSS と ERR は 1 回目も正しい。

| | 1 回目 | 2 回目 | 3 回目 |
|---|---|---|---|
| 送った音・ペダル・ベンド | 2106・110・494 | 同じ | 同じ |
| テイクのノートの数（ピアノロールの帯の「ノート」） | 2106 | 2106 | 2106 |
| ERR（xrun）: meloet のストリーム | 0 | 0 | 0 |
| ERR: アナログの出口 | 3 秒目に 1（録音の前、ストリームを開いたとき）。そのあと 0 | 同じ | 同じ |
| GC の助手が動いた秒（1 秒に 20 ms 以上） | （数えかたのまちがいで、数えていない） | 311 秒 | 261 秒 |
| xrun と GC が 1 秒以内に重なった | なし | なし | なし |
| meloet の RSS | 57 → 225 MB（30 秒からあとは 224〜225 で平ら） | 57 → 226（平ら） | 57 → 226（平ら） |
| WebKitWebProcess の RSS（はじめ → いちばん大きい → 終わり） | 336 → **806** → 806（ずっと増えつづけ、**360 秒で 600 MB をこえた**） | 336 → 496（180 秒）→ 404 | 337 → 509（210 秒）→ 408 |
| 再生して鳴ったか（20 秒の RMS） | -40〜-50 dBFS（ピーク -29〜-41） | 同じ | 同じ |

- 2 回目と 3 回目は、約 3 分で 500 MB ほどまで増え、そこで GC にあたるらしい下がりかた（約 70〜90 MB）があり、そのあと 7 分は平らか、少しずつ下がった。宿題 3 の 10 分（277 → 565 → 473 MB で平ら）と同じ形。
- 1 回目は、その下がりかたが一度もないまま、まっすぐ（約 0.75 MB/秒）増えた。同じ条件で 3 回のうち 1 回。何がちがったかは、まだわからない（宿題 3 の見はりの案の「600 MB をこえない」は、1 回目で破れた）。
- 再生の最初の 2 秒（-42/-15 dBFS）は、録るのを始めたのが再生の 3 秒前なので、その間の音（止めた直後のメトロノームの残り）。そのあと 4 秒は無音で、再生が始まると鳴っている。
- late（エンジンの中の「遅れたコールバック」の数）と、cpal のストリームのエラーの数（`EngineMeters::late_callbacks`、`streams_lost`、`other_errors`）は、アプリの外から読めないので数えていない。PipeWire の ERR（xrun）は読めた。
