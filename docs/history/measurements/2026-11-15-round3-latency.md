## 悪くなった所: 1280×800 の録音中、録り始めの 2 鍵め

- 3 回のうち 2 回で、録音の最初の鍵のすぐあとの鍵が 87〜144 ms おくれた（2 コマの線をこえた）。どちらも 120 鍵のうち、録音の 2 鍵めと 3 鍵めだけ。Rust → JS がすでに 84〜140 ms で、画面の主スレッドがふさがっていた。
- `frame-profile.json` で、そのときのコマ: 録音の最初のノートが出た次のコマが `measureMs` 204 ms、`busyMs` 224〜230 ms で、`pianoRollLive`（録音中にのびるノートの区画）を初めて描いている。spaced の回も同じコマ（204 ms）があるが、次の鍵が 257 ms あとなので、鍵の数には出なかった。
- 1920×1080 の録音中にも同じ大きさのコマ（204 ms）が 1 つある。こちらは録音が始まった瞬間（アレンジの `recordingClip` を初めて描くコマ）で、鍵より前なので数には出ない。1280×800 ではアレンジに録っているクリップの区画が出ないので、ピアノロールの `pianoRollLive` を初めて描く、最初のノートのときに来る。
- どの回も、ページを読んだ直後に 860〜870 ms、ピアノロールの帯をひらいたコマに 55 ms の `measureMs` がある（鍵の前）。
- 見立て（確かさ C: 測った数とコードからの読み）: `engine.ts` の `measureMs` は、箱を測る時間と `place()`（canvas の大きさと、まだない区画の canvas を池から取る所）をふくむ。区画が初めて canvas を持つときに WebGL の文脈を作り、それが WebKitGTK（NVIDIA）で約 200 ms 主スレッドを止める。ノートのドラッグも同じ形で、1 回目のドラッグのコマが 104 ms（`pianoRollLive` を初めて描く。`2026-11-15-round3-pianoroll-10k.md`）。
- 確かめていない事: 時間が本当に `getContext` の中か（`place()` の中を分けて測っていない）。案: 起動のときに、あとで要る区画の数だけ文脈を作って池に入れておく、など。直していない（`ui/src/gl/` の engine と pool は今回さわれる所の外）。

## e. 前の鍵から 34〜150 ms あけた鍵が、ときどき待つ理由

mixed の回では、前の鍵から 34〜150 ms の鍵の多く（例: 1920×1080 止まっている、35 鍵のうち 27）が 2 ms より待った。待った時間 ＋ 前のコマからの時間 ≒ 16 ms で、次の 60 Hz の刻みまで待っている。150 ms より後の鍵は、どれも待たない。

鍵を「押した瞬間に、ほかの鍵がまだ押されていたか」（`vkeys.json` の押す・離す時刻）で分けた（`pr-1920-stopped-mixed`、`pr-1920-playing-mixed` と `pr-1920-recording-mixed` を合わせた物）:

| 前の鍵から | ほかの鍵 | 1920 止まっている n（待った） | 1920 再生中と録音中 n（待った） |
|---|---|---|---|
| 0〜16.7 ms | 押されている | 30（18） | 68（19） |
| 0〜16.7 ms | ない | 2（0） | 4（0） |
| 16.7〜33.3 ms | 押されている | 4（2） | 12（7） |
| 33.3〜150 ms | 押されている | 29（**27**） | 35（**24**） |
| 33.3〜150 ms | ない（50 ms 以内に離した） | 6（**0**） | 20（**0**） |
| 150 ms〜 | ない | 48（0） | 99（0） |

- わかった事: 待つかどうかは、前の鍵からの間ではなく、**押したときにほかの鍵がまだ押されているか**で分かれる。押す長さは 120 ms なので、34〜120 ms の鍵は前の鍵を押したまま、125 ms より後の鍵は離したあと。離した直後（50 ms 以内、メーターがまだ動いている）の鍵も待たない。
- 第 2 回の「仮想の鍵盤の 60〜140 ms は 80 鍵とも待たなかった」と、本物の鍵盤の 34〜150 ms がときどき待ったのも、これで読める（本物の人はレガートで前の鍵を押したまま次を押す。確かさ C）。
- わからなかった事: 押している鍵があると、なぜ次の鍵の絵が次の刻みまで待つのか。どちらのときも直前のコマの間は 16 ms で、描いた区画（入力計の鍵盤、ピアノロールの鍵盤の列、メーター）にも大きなちがいはなかった（`frame-profile.json` の、鍵の前 3 コマ）。鍵が離れていると、鍵が来るとすぐコマが来る（待ち 0〜1 ms）。見立て: 鍵が押されている間は計器（押している鍵の一覧と、鳴っている音のメーター）が 60 Hz で届きつづけ、すでに次の刻みのコマが頼まれているので、鍵の絵がそのコマにのる（確かさ C、未確認）。確かめるには、計器が届いた時刻とコマを頼んだ時刻を `frame-profile.json` に足して、ならべる。
- 「和音の 2 つめから先が 1 コマおくれるのはかまわない」（仕様書 3 章）。押したままの鍵のあとの鍵も、待つのは 1 コマ以内で、2 コマの線はこえていない（上の録り始めの 2 鍵めは別の理由）。
