# 第 8 回 区切り4 音のスレッドの優先度（2026-11-22、meloet-hard ・ Opus 5.5、印 k8rt）

決めた事は `docs/architecture.md` の 23-10。前の測りは `2026-11-22-round8-quiet.md` の 2 章（`pw_out` が `SCHED_OTHER` ・ nice 0 だった）。

## 条件

- 版: foundation b30cf61 ＋ この区切りの書きかえ（`crates/meloet-engine/src/priority.rs`）。release（`ui/dist` を作りなおし、`cargo build --release -p meloet-app -p meloet-plughost -p meloet-midi`、`CARGO_TARGET_DIR=target/k8rt`）。
- 曲: `make_song.py --tracks 16 --notes 540 --bars 72 --stagger 7 --instruments plugin --plugin "Surge XT" --effect-plugin ZamComp`（quiet の 2 章と同じ引数。`--scan` は `target/shoot/cache/meloet/plugins/scan.json`）。
- 形: `app-watch.sh --seconds 170`、2.5 秒目にミキサー、7 秒目から再生。WebKit は CPU の道（この版の既定。`crates/meloet-app/src/main.rs` の `WEBKIT_DISABLE_COMPOSITING_MODE=1`。quiet の 2 章は合成の道だった）。横で `long_record_watch.py`（pw-top の ERR と BUSY）、`plug_watch.py`、起動 30 秒と 90 秒に `ps -L -o pid,tid,cls,rtprio,ni,comm`。
- くらべかた: 同じビルドで、`MELOET_ENGINE_RT=off`（頼まない ＝ 前の形）と既定（頼む）を交互に。
- quantum: 変えていない（`clock.force-quantum` 256 のまま）。
- この PC の meloet-agent は `audio` グループ（`ulimit -r` 95）。どの回も `sched_setscheduler` の道で上がった（記録の文 `meloet: the audio output thread runs at real-time priority 20 (limit)`）。rtkit の道は、このユーザーでは polkit に断られる（`MELOET_ENGINE_RT=rtkit` で `rtkit: Operation not permitted`。座席のないセッションなので `allow_any` = no に当たる、と読んだ。確かさ C）。**rtkit の道で上がる所は確かめていない**。
- スクラッチと生の数: `target/k8rt-meas/`（`a-*` ・ `b-*` ・ `lat-play/`）。

## 本物で見たスレッドの優先度

| | `MELOET_ENGINE_RT=off` | 既定 |
|---|---|---|
| meloet の `pw_out`（30 秒 ・ 90 秒） | TS、nice 0 | **FF 20** |
| 弾くほうの係の `plughost-audio-*`（2 プロセス × 4 本） | FF 20 | FF 20 |

- 入口の `pw_in` は、本物のアプリの測りでは入口をひらいていないので、`meloet-engine` の試験（`tests/device.rs` の `real_inputs_open_run_and_close_without_touching_the_allocator`、本物の PipeWire）を走らせながら `ps -L` で見た: `pw_out` も、3 回ひらいた `pw_in` も FF 20。同じ試験の、コールバックの中でメモリを取らない見はりは通った。
