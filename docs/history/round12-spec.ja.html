3. 録る・弾く

R1 さかのぼり録音

ねらい：録音を押していなくても、直前に弾いたものをクリップにできる。

ふるまい

  1. ためる：録音中とカウントイン中でないとき、弾く先のトラックへ届いた鍵盤の出来事（ノートのオンとオフ、CC、ピッチベンド。ベロシティ固定をかけたあとのもの）を、いつも「さっきの演奏」としてためます。E2 のアルペジオがオンのトラックでは、実際に鳴ったノートをためます。
  2. 位置は届いた時に控える：エンジンの時計が覚えているのは直近 512 ブロック（0.7〜2.7 秒）だけなので、後から計算し直せません。エンジンの read_midi で、いつも（録音でないときも）耳に届いていた位置を控え、Recorded の輪に新しい種類（Recent）として積みます。控えるもの：出来事、t_us、位置（再生中）、再生中か止まっているか、ループの何周目か。再生中のループの周回は今数えていないので、エンジンで数えます。
  3. 区切り：再生と停止が切り替わったら、ためたものに「閉じた」印をつけます。閉じたあとに新しいノートオンが来たら、古い分を捨てて新しくため始めます（再生しながら弾く → 止める → 残す、ができます）。止まっているときは、鍵もペダルも離れたまま「いまのテンポで2小節ぶんの時間」が過ぎたら、次のノートオンで新しくため始めます。
  4. 捨てる時：残したあと、録音が終わったとき、弾く先のトラックが変わったとき、曲を開く・新しくするとき。上限は出来事 4096 個と 10 分。あふれたら古い方から捨てます。
  5. 残す（KeepPlayed）：
    • 再生中に弾いた分：控えた位置にそのまま置きます。ループしていたら、周ごとにテイクになります（ループ録音と同じ Recorder の決まり）。
    • 止まっているあいだに弾いた分：最初のノートを「再生線のある小節の頭」に置き、あとは経過時間を、再生線の位置のテンポで位置に直します（テンポの変化は見ません。テンポを当てることもしません）。
    • クリップは小節の頭から小節の終わりまで。押したままの鍵は、残した時刻で切ります。
    • トラックへの置き方は録音と同じです：Recorder::new / push / finish → edit::add_recording（重なるクリップはまとめる）。「重ねる」がオンなら overdub::overdub_recording。Play::apply_selecting で1ステップにし、できたクリップを選びます。再生は始めません。
  6. 断るとき：カウントイン中と録音中、キーのトラックが弾く先でないとき、ノートが1つもないとき。最後の場合はステータスラインに「残せる演奏がありません」。

画面と文言

  • 上の帯の「重ねる」の右にボタン「さっきのを残す」。残せるものがないあいだは無効。キーは Shift R。メニュー「再生」に「さっきの演奏を残す」。
  • ステップ名「さっきの演奏を残す」。

約束と作り

  • 約束：Command::KeepPlayed、TransportView.can_keep_played: bool（0 個かどうかが変わったときだけ変える。60 Hz で変えない）、StepName::KeepPlayed。
  • エンジン（crates/meloet-engine/src/engine.rs の read_midi と stamp、clock.rs）、コア（service.rs の poll_engine と record_report、play.rs にためる所と keep_played）、モデルは今ある関数を使う、画面（Transport.svelte、keys.ts、menus.ts）。

テストと受け入れ

  • エンジン：再生中と停止中に控えた位置が、録音のときと同じ精度であること（tests/transport.rs の recorded_keys_get_the_position_that_was_heard と同じ形）。every_transport_path_stays_off_the_allocator に足す。
  • コア：区切りの決まり、ループの周がテイクになること、「重ねる」、1ステップで戻ること。
  • 自前の PipeWire のテスト（record_timing_private の形）で、再生中に弾いて残したノートの位置の誤差が、録音と同じ範囲であること。

わな

  • 出口がひらいていないあいだの鍵はエンジンへ行かないので、ためられません（今の作り）。
  • 止まっているときはコアの見回りが 100 ms おきです。輪は 4096 なので足りますが、あふれの数え（record_overflows）は見ます。
  • 「クオンタイズは編集だけ」。残すときに位置をそろえません。

R2 パソコンのキーボードで弾く

ねらい：MIDI 鍵盤がなくても、文字のキーで音を出して録れる。

ふるまい

  1. 入力の帯のボタン「キーで弾く」か Mod K で入切。Esc でも切れます（Esc の順は、ドラッグの中止やメニューを閉じるより後、「ひとつ戻る」より前）。起動時は切。設定には残しません。
  2. キーは物理の位置（event.code）で決めます。白鍵：A S D F G H J K L ; が C D E F G A B C D E。黒鍵：W E が C# D#、T Y U が F# G# A#、O P が C# D#。Z と X でオクターブを下げる／上げる（A の音は C0〜C7、はじめは C3）。
  3. ベロシティは 100。ベロシティ固定がオンならその値（今ある fixed() を通るので、何もしなくてそうなります）。
  4. オンのあいだ、修飾キーなしの文字と数字のキーは、ショートカットとして働きません（鍵に割り当てていないキーも）。Mod つきのキー、Space、矢印、Delete、Home、F キー、Esc は今までどおり。
  5. 文字を打っているとき（isTyping）は鍵になりません。長押しのくり返し（ev.repeat）は捨てます。keyup でノートオフ。ウィンドウが前でなくなったとき、切ったとき、オクターブを変えたときは、押している音を全部離します。IME の変換中のキーは今も捨てているので、日本語入力がオンだと鳴りません。ステータスラインのヒントにそう書きます。
  6. 本物の鍵盤と同じ扱い：音、入力のメーター、録音、R1、E2 のどれにも、本物と同じに効きます。鍵盤の一覧に「パソコンのキーボード」という名前の鍵盤として、オンのあいだだけ現れます（出口をえらぶ画面の「鍵盤が1台以上」の条件も、これで満たします）。

約束と作り

  • 約束：Command::TypedKeys{on: bool}（入切）、Command::TypedKey{note: u8, down: bool, t_us: u64}。t_us は画面が ev.timeStamp から Rust の単調時計に直した時刻（あいさつで受け取る mono_us の差を使う。再生線と同じやり方）。録音の位置はこの時刻で決まります。
  • 道：今の試聴（Audition）は録音もメーターも通らないので使いません。MIDI の輪は MIDI のスレッドだけが書けるので、コアのスレッドからエンジンへの輪をもう1本作り、read_midi で MIDI の輪と一緒に時刻順に読みます。コア側は play_key と同じこと（Held の更新、Event::Note を画面へ）をします。Hands に「パソコンのキーボード」を1台として持たせ、切るときに全部離します。
  • 画面：ui/src/keys/attach.ts の handleKeydown で、Esc の枝のあと、laneDeleteCommand などの前に入れます。handleKeyup に本物の処理を足します。InputMeter.svelte にボタンと「オクターブ C3」の表示。ステータスラインに「キーで弾く：オン。1文字のショートカットは止まっています。Z ／ X でオクターブ、Esc でやめる」。

テストと受け入れ

  • コア：このキーが音、テイク、メーター、画面の全部に届くこと（service/tests.rs の固定ベロシティのテストと同じ形）。切ったとき全部離れること。
  • 画面：割り当て、くり返しを捨てる、ショートカットが止まる、文字入力中は効かない。
  • 測る：キーを押してから音が出るまで。tools/measure/remote.py で偽のキーを送り、出口を録って測り、数を docs/measurements/ に書きます。目安は MIDI 鍵盤の遅れ＋1フレーム以内。届かなくても止めず、数を報告します。

わな

  • Core::send はコアの返事を待ちます。押すたびに画面が待たされるなら、返事を待たない送り方（急ぎの道）にします。
  • キーを離す出来事が来ないことがあります（ウィンドウを切り替えた瞬間）。blur と visibilitychange で全部離します。

P3 ベロシティと長さの道具

ふるまい（どれも、選んだノートに1ステップ）

  1. 割合：10〜300 %（はじめ 100）。round(v × 割合 / 100) を 1〜127 に収めます。
  2. だんだん：はじめ（1〜127）と終わり（1〜127）。選んだノートのうち、いちばん早い始まりを「はじめ」、いちばん遅い始まりを「終わり」として、始まりの位置で直線に割ります。同じ始まりのノートは同じ値。全部が同じ始まりなら「はじめ」の値。
  3. ばらつき：±1〜32（はじめ 8）。ノートごとに −n〜+n の整数を足して 1〜127 に収めます。乱数の種は画面が押すたびに作って意図に入れます。Rust は（種、ノートの番号）から決まる計算をします（モデルに乱数源はありません。splitmix の小さな関数をモデルに足します）。同じ意図は同じ結果になります。
  4. 次の音までのばす：選んだノートの終わりを、それより後に始まる「選んだノートのうち、いちばん近い始まり」までのばします（短くもなります）。同じ始まりのノート（和音）は同じ終わり。いちばん後ろのノートは変えません。長さは1ティック以上。
  5. 変化が1つもなければステップを作りません（今の EditError::Unchanged）。

画面と文言

  • インスペクタの「ベロシティをまとめて変える」の節に行を足します：「割合」と数字と「かける」、「だんだん」と数字2つと「かける」、「ばらつき」と数字と「かける」。「長さをそろえる」の節に行「次の音までのばす」と「のばす」。今ある bulkRow の形（数字の欄、Enter、Esc、↑↓、Shift で10倍）に合わせます。
  • ステップ名：「ベロシティを割合で変える」「ベロシティをだんだん変える」「ベロシティをばらつかせる」「次の音までのばす」。

E2 アルペジオとノートリピート

ふるまい

  1. トラックごとの設定です。入力の帯に「アルペジオ」ボタン（弾く先のトラックのオン／オフ）と ▾（設定の小さな窓）。ミキサーのストリップの「音源」の上の席（spec 3 の L41 で取ってある場所）に、オンのとき「アルペジオ」と出し、押すと入切できます。
  2. 設定：形 上へ／下へ／上下／ばらばら。速さ 1/4、1/8、1/16、1/32 と「三連符」の入切。オクターブ 1〜3。指を離しても続ける オン／オフ。音の長さは1つぶんの 80 %（固定）。
  3. 押さえている鍵（16 個まで）を、形の順に、速さの間隔で1つずつ鳴らします。ベロシティは、その鍵を押した強さ。鍵が1つなら連打（ノートリピート）になります。
  4. 再生中は曲のグリッドに合わせます（小節の頭から数えた間隔の位置で鳴る。押した瞬間ではなく、次の位置から）。止まっているときは、最初の鍵を押した時を起点に、いまのテンポで進みます。
  5. かかるのは鍵盤から来た音だけです（MIDI 鍵盤と R2 のキー）。曲の中のノート、試聴、コード表の試聴にはかかりません。
  6. 録音：オンのトラックでは、押した鍵ではなく、鳴ったノートを録ります。位置はグリッドの位置そのものです。再生するときはそのノートが音源へ直接行くので、二重にかかりません。CC とペダルはそのまま通り、そのまま録ります。
  7. 「続ける」で残っている音は、次のどれかで止めます：アルペジオか「続ける」を切る、弾く先を変える、CC 123 / 121、全部離したあとに新しい鍵を押す（新しい和音に入れ替わる）。
  8. 設定は曲に入り、変えるたびに1ステップ（「アルペジオを変える」）。

約束と作り

  • モデル：Track に arp: Arp{on, shape, rate, triplet, octaves, hold}（#[serde(default)]）。曲ファイルに欄。約束：SetArp{track, arp}、トラックの見え方に arp、StepName::SetArp。
  • エンジン：read_midi で、アルペジオがオンのトラック宛ての鍵盤のノートを、音源へ渡さずにアルペジオの状態（固定長の配列。割り当てなし）へ入れます。render はクリックやノートの位置でブロックを切っています（frames_to_next_point）。そこにアルペジオの次の位置を足し、位置ぴったりのフレームで音源の event を呼びます。テンポは Transport から取ります（傾きのあるテンポでも）。
  • 録音：作ったノートを、グリッドの位置をつけて Recorded の輪へ積みます（押した鍵は積まない）。R1 の「さっきの演奏」にも、鳴ったノートが入ります。
  • EngineOp に設定を渡す種類を足し、ExportEngine::tell と Audio::op の網羅の match を直します。書き出しには鍵盤の出来事がないので、何も鳴りません。
  • 画面：InputMeter.svelte、mixer/Strip.svelte、文言（形4つ、設定の名前、「アルペジオ」）。

テストと受け入れ

  • エンジン：再生中、作った音の出だしがグリッドのフレームと 0 フレームの差で合うこと（クリックのテストと同じ見方）。ループの継ぎ目、テンポの傾き、三連符。割り当てなし（every_transport_path_stays_off_the_allocator と rt-check）。
  • 録ったテイクのノートがグリッドの位置にあること。再生で二重にかからないこと。弾く先を変えたとき、鳴りっぱなしの音が残らないこと。
  • オフのとき、キー → 音の遅れが変わらないこと（latency.sh）。

わな

  • 「耳に届いていた位置」の決まりは、押した鍵のためのものです。作ったノートは、鳴らす位置（グリッド）がそのまま曲の位置です。出口の遅れぶん後に聞こえますが、再生でも同じだけ遅れて聞こえるので、合っています。
  • 「ばらばら」の乱数は、鳴ったものをノートとして録るので、再現の決まり（architecture 22-25）にはかかりません。

E3 音のつまみ（内蔵の音）

ふるまい

  1. 内蔵の音（サンプルの音と計算で作る音）のトラックを選ぶと、右のパラメータのパネルに4つの行が出ます：「明るさ」「立ち上がり」「のび」「ゆれ」。今は「この音にはパラメータがありません」の所です。形は内蔵エフェクトの行（ParamRow）と同じにします（図は作りません）。
  2. 値は 0〜100 %。はじめは 明るさ 50、立ち上がり 50、のび 50、ゆれ 0。はじめの値のとき、音は今と1サンプルも変わらないこと。
  3. 明るさ：音源の出口にかける傾きのフィルター。50 より下はローパスが閉じていき（0 で 400 Hz）、上はハイシェルフで持ち上げます（100 で 4 kHz から上を +9 dB）。50 ちょうどは素通し。
  4. 立ち上がり：50 より下は立ち上がりの時間に 2×値 をかけ（0 でいちばん速い）、上は時間を足します（100 で +400 ms）。ノートオンのときの値で決まります。
  5. のび：離したあとの時間に 4^(2×値−1) をかけます（0 で 1/4、100 で 4 倍）。ノートオフのときの値で決まります。
  6. ゆれ：音の高さを 5.5 Hz でゆらします。深さは 0〜50 セント。
  7. ドラムのキット（スタジオ、エレクトロ、ブラシ）では「明るさ」と「のび」だけ使え、ほかの2行は無効で出します。サイン波は4つとも使えます。SF2 とプラグインの音には出しません（プラグインは今の一覧のまま）。
  8. ミキサーのつまみと同じ動かし方です：ドラッグ中は音だけ変わり（commit: false、1フレームに1回まで）、離したとき1ステップ（「音のつまみを変える」）、Esc で CancelMixPreview。数字はダブルクリックで打てます。オートメーションの印が使え、レーンで動かせます。
  9. 音源を入れ替えたら、4つともはじめの値に戻します。

約束と作り

  • モデル：Track に knobs: SoundKnobs（4つの値。#[serde(default)]）。曲ファイルに欄。オートメーションの的は今ある AutoTarget::Instrument{param} を、内蔵の音でも param 0〜3 で使えるようにします（has_target と check_lanes を直す）。
  • 約束：SetSoundKnob{track, knob, value, commit}、選んだ音の見え方（SelectedParams::Sound）に4つの値と使える／使えない、StepName::SetSoundKnob。
  • エンジンと音：Instrument の set_param_at(frame, id, v) は内蔵の音では今は何もしません。ここを作ります。値は 20 ms でなめらかに。
    • 明るさは、内蔵の音を包む共通の部品（出口のフィルター。トラックごとの状態）にします。サンプルの束は複数のトラックで共有（Arc）なので、状態を束に置いてはいけません。
    • 立ち上がりとのびは、サンプルの声（sampler/player.rs の Voice。今は instrument.json の値で固定）と、計算で作る音（synth/poly.rs の Patch の ADSR）に、かけ算と足し算で入れます。
    • ゆれは、声ごとの LFO。位相は声が始まるときに 0 から。走りっぱなしの LFO は使いません。
  • 画面：params/ の一覧（内蔵の音のとき4行を出す）、AutoMark.svelte、文言。

テストと受け入れ

  • はじめの値で、今の出力と1サンプルも変わらないこと（今ある音のテストがそのまま通る）。
  • はじめでない値でも、書き出しと再生が1サンプルまで同じこと（what_is_exported_is_what_plays_sample_for_sample と crates/meloet-sound/tests/song_places.rs に、つまみを動かした場合を足す）。曲のどこから再生しても同じ音になること。
  • 割り当てなし（sampler_rt.rs、synth_voices.rs）。NaN とデノーマル。速さ（--ignored の速さのテスト）が、はじめの値で悪くなっていないこと。

6. 編曲とアレンジ

A1 クリップをくり返す

ふるまい

  1. 持ち手：クリップの角に空きはありません（右端は長さの変更、音のクリップは名前の帯のすぐ下にフェードの持ち手）。空いているのは「名前の帯の高さの右端」だけなので、そこを持ち手にします：幅 12 px（クリップの幅の 1/3 まで）、高さは名前の帯。その下の右端は今までどおり長さの変更です。マウスが乗ると印（⟳）が出ます。クリップが狭くて名前の帯が出ないときは持ち手もなく、メニューだけです。
  2. 持ち手を右へ引くと、クリップの長さごとに、写しの枠が増えます（まるごとの写しだけ。半端は作りません）。となりのクリップの手前と曲の上限で止まります。離すと意図が1つ。Esc で止まります。
  3. メニュー：クリップの右クリックと「編集」に「くり返す…」（Mod R）。その場に数字の箱（はじめ 3、1〜99）。Enter で決まり、Esc でやめます。
  4. 写しは、元の終わりにぴったり続けて置きます。長さが小節の倍でなくても、そのまま続けます。
  5. いくつも選んでいるときは、選んだクリップぜんたいを1かたまり（いちばん早い始まりから、いちばん遅い終わりまで）として、その長さごとに写します。今の複製（Mod D）と同じ考えです。
  6. できるのはふつうのクリップです（新しい ID。テイクは共有していて、編集すると新しいテイクになるので、あとで別々に変えられます）。オートメーションは写しません。キーのクリップでも音のクリップでも使えます。
  7. ほかのクリップに重なる回数を頼まれたら、何もせず、今ある「重なる」の知らせを出します（全部か、なしか）。全部で1ステップ（「クリップをくり返す」）。

約束と作り

  • 約束：RepeatClips{clips, count}、StepName::RepeatClips。モデル arrange.rs：duplicate_clips をもとに、回数ぶんを1つの Edit で。コア play.rs（duplicate_clips の隣、apply_placed）。
  • 画面：arrangeDrag.ts の clipHit に持ち手の当たりを足す（音のクリップでは AudioClipHandles.svelte が先に受けるので、当たりの順に注意）、Arrange.svelte（ドラッグ中の枠は、今の動かす絵と同じ小さな枠 recordingClip に）、clipEdits.ts、menus.ts、keys.ts。

テスト

  • モデル：1つと複数、重なりで何もしない、上限。画面：持ち手の当たり（長さの変更とフェードを壊さない）、Esc、離して1つの意図。tools/measure/ui-script.sh のドラッグで、フレームが悪くなっていないこと。

A2 区間（セクション）ごと動かす

ふるまい

  1. 区間は、あるマーカーから次のマーカーの手前まで（最後のマーカーは、曲の終わりを小節に切り上げた所まで。今の loop_from_marker と同じ決め方）。
  2. マーカーの右クリックのメニューに3行足します：「この区間をすぐ後ろに複製」「この区間を消して詰める」「この前に空きを入れる…」。
  3. 区間の両端が小節の頭のときだけ使えます。ちがうときは無効で、ツールチップ「区間の両端が小節の頭のときに使えます」。拍子の変更は小節の番号で持っているので、小節の単位でしか動かせないからです。
  4. 空きを入れる（位置 at、n 小節。箱のはじめは 4、1〜64）：at より後ろを、at の拍子での n 小節ぶん後ろへ動かします。
    • クリップ：at をまたぐものは at で切り、後ろの半分を動かす。
    • オートメーションの点（全トラックと、M5 のマスター）：at 以後を動かす。at の直前の値の点を at に足し、空きのあいだは平らにする。
    • マーカー：at 以後（at ちょうども）を動かす。
    • テンポの点：at 以後を動かす。傾きの途中に at があるときは、at に「そのときのテンポ」の点を足し、空きのあいだは平らにし、空きの終わりから元の傾きを続ける。
    • 拍子の変更：at の小節より後ろの番号に n を足す。
    • ループ：at より後ろにあれば両端を、at が中にあれば終わりだけ動かす。
  5. 消して詰める（from〜to）：両端でクリップを切り、中のクリップ、点、マーカー（区間の頭のマーカーも）、テンポの点、拍子の変更を消し、to より後ろを前へ詰めます。詰めた継ぎ目では、to のときのオートメーションの値、テンポ、拍子が from から続くように、要る点を足します。ループがまるごと中にあれば消します。
  6. 複製（from〜to）：to に区間の長さの空きを入れ、区間の中身を写します：クリップ（両端で切ってから。新しい ID、テイクは共有）、オートメーションの点、テンポの点、拍子の変更、マーカー（頭のマーカーも同じ名前で）。写しの頭では、区間の頭と同じテンポと拍子になるよう点を足し、写しの終わりでは、元の「to から先」のテンポと拍子が続くよう点を足します。
  7. どれも1ステップ（「区間を複製」「区間を消して詰める」「空きを入れる」）。曲の上限（MAX_TICK）を越えるなら断ります。選択は外し、再生線は動かしません。

約束と作り

  • 「ある位置から後ろを全部ずらす」処理は今どこにもありません。モデルに新しいファイル crates/meloet-model/src/sections.rs を作り、insert_time、remove_time、duplicate_range を、1つの Edit を返す関数として作ります。
  • 曲の位置を持つもの（全部動かすこと）：Clip.start/end、全トラックの Lane.points[*].tick、Doc.markers[*].tick、tempo_points[*].tick、meter_changes[*].bar（小節の番号）、Doc.loop_range、M5 のマスターのレーン。動かさなくてよいもの：テイクの中のノートと CC（テイクからの位置）、ClipTake.offset、フェード、AudioTake.sync。
  • 約束：DuplicateSection{marker}、DeleteSection{marker}、InsertSpace{marker, bars}、ステップ名3つ。コア play/timeline.rs。画面 timeline/MarkerRow.svelte（メニュー L107-119 に3行と区切り）。

テストと受け入れ

  • 性質のテスト：空きを入れてから同じ所を消すと元に戻る（ID を除く）。複製してから写しを消すと元に戻る。操作のあとも Timeline::check() が通る。区間より前の位置の時刻が変わらない。区間より後ろのノートの「前後の間隔の時間」が変わらない。
  • 傾きのあるテンポの途中、拍子の変わり目、音のクリップ（切っても音が変わらない。audio_app.py same）、テンポについていく音のクリップ（作り直しが走る）、ID の台帳（id_book.rs）。

わな

  • オートメーションを変えるとレーンの ID が新しくなります。画面の古い ID の意図は何もしません（それで正しい）。
  • クリップを切ると、音をまたぐキーのクリップの左半分は新しいテイクになります（今の split_clips の決まり）。

A7 キーのトラックを音のクリップにする

  2. 鳴らし方：そのトラックだけを、音源とインサートを通して、フェーダー 0 dB、パンまんなか、センドなし、マスターのインサートなしで鳴らします。余韻は音が消えるまで（最大 10 秒）。
  3. できた音は、すぐ下に作る新しい歌（音）のトラックに置きます。名前は「元の名前（音）」。新しいトラックの音量、パン、センドは元のトラックから写します。インサートは写しません（もう音に入っているので）。元のトラックは消さずにミュートします。トラックを足す、クリップを置く、ミュートする、を合わせて1ステップ（「音のクリップにする」）。取り消すと全部戻ります。
  4. 鳴らすのは裏の仕事です。ステータスラインに「音にしています… 40 %」と「やめる」。できあがったときに元のトラックがまだあれば置き、なければ捨てて知らせます。
  5. 断るとき：カウントイン中と録音中、書き出しのダイアログがひらいているとき、AI 連携の書き出しや別の「音にする」が走っているとき（裏の仕事は1つずつ）、トラックが 64 本のとき。
  6. できた音のクリップは「曲のテンポについていく」をオフで置きます。ファイルは設定の録音の形（16 / 24 / 32 ビット）、エンジンのサンプルレート。

約束と作り

  • AI 連携にもう近いものがあります：crates/meloet-core/src/state/ai.rs の ai_render_job と clip_doc（そのトラックとそのクリップだけの Doc を作って書き出しの仕事に渡す）。これを「範囲」と「インサートあり、フェーダー 0 dB、マスター素通し、余韻あり」で使えるように広げます。clip_doc はクリップの種類を見ていないので、キーのクリップで確かめます（未確認）。
  • 書き出しの仕事（export/job.rs）は別のスレッドで、プラグインは書き出し用のプロセスに生きた状態で載ります（今の作り）。
  • できたファイルは、録音や読み込みと同じ道で曲に入れます：作業の場所（<state>/work/音/）へ、AudioStore（audiofiles.rs）に知らせ、AudioSource を作り、ピークは keeper が作る。名前は vocalrec::file_name の形。保存のときに 音/ へ移ります。
  • 約束：BounceToAudio{clips: Vec<u32>}、BounceTrack{track}、CancelBounce、進み具合の見え方（ExportRunView と別の小さな見え方）、StepName::Bounce。画面 Arrange.svelte の clipMenu、trackMenu.ts、StatusLine.svelte。

テストと受け入れ

A8 歌のいいとこ取り（コンピング）

ふるまい

  1. 歌のクリップで、テイクが2つ以上あるものが対象です。キーのクリップは今回やりません。
  2. クリップの右クリックに「いいとこ取り」。トラックの下に帯がひらきます。場所と形は spec 3 の L282 のあたりに取ってある席の記述を先に読み、それに従います。下は、そこに書いていない所の決まりです。
  3. 帯にはテイクごとの行（波の形。新しい方から 8 行まで）。行の上を横に引くと、その範囲はそのテイクが鳴るようになります。引いているあいだは画面だけが変わり、離すと意図が1つ。端は、見えているグリッドの線に寄ります（Shift で寄せない）。選ばれている範囲は color.accent で示します。
  4. 「もとに戻す」で、いいとこ取りを外し、クリップは「表示中のテイク」1本に戻ります。
  5. 継ぎ目は 10 ms のクロスフェード。プチッと鳴らないこと。
  6. いいとこ取りがあるクリップで「次のテイク／前のテイク」（T）を押すと、いいとこ取りを外してそのテイクまるごとにします（1ステップなので戻せます）。「テイクを消す」は、いいとこ取りがあるあいだ無効。クリップを切ると、範囲も切れます。長さを変えると、範囲はクリップの中に収まります。
  7. テイクは変えません（「テイクは、できたら中身が変わらない」）。変わるのはクリップの「どの範囲でどのテイクを鳴らすか」だけ。1ステップ（「いいとこ取り」）。

約束と作り

  • モデル：Clip に comp: Vec<CompPiece{from: u64（クリップの頭から）, take: usize}>（空ならなし。#[serde(default)]）。あれば、鳴らすときに active より優先します。歌のクリップのテイクは、同じ録音のファイルの周ごとの区切りで、形（フェード、音量、ストレッチ）はクリップに1つなので、位置はそろっています。
  • エンジンへ：コアは今、クリップごとに1つのテイクをクリップの表（EngineOp::Clips、play/audiosync.rs）にして送っています。いいとこ取りのあるクリップは、範囲ごとの行に分けて送り、継ぎ目に 10 ms のフェードをつけます。同じトラックで行を重ねられるなら重ねて、できなければ先読み（readahead.rs）の入れ替えのクロスフェードの考えを使います。どちらにするかは読んで決め、architecture に書きます。
  • 書き出しは同じ道を通るので、何もしなくても同じ音になるはずです（確かめる）。ストレッチした音（「作った」ファイル）はテイクごとにあります。
  • 約束：SetComp{clip, pieces}、ClearComp{clip}、クリップの見え方に comp、帯をひらく／閉じるは画面の状態。画面：帯の行は、オートメーションのレーン（automation/AutoLane.svelte）と同じく arrangeLanes 領域の枠として描きます（新しい領域は作らない）。

テストと受け入れ

  • テイクをまたぐ継ぎ目で、音の飛びがしきい値より小さいこと（どのテイクも同じサイン波のとき、出力がサイン波のままであること）。書き出しと再生が同じ（export_app.py same）。切る、長さを変える、テイクを切り替える、取り消し。
  • audio_app.py arrange と arrange_parts.py で、帯をひらいたときのフレーム。

A9 音のクリップを逆にする・ノーマライズ

ふるまい

  1. 音のクリップの右クリックの、今は無効の2行「逆にする」「ノーマライズ」を使えるようにします（文言は今のまま。出どころ spec:3）。いくつも選んでいれば、それぞれにかけて1ステップ。
  2. ノーマライズ：新しいファイルは作りません。表示中のテイクが使っている範囲のいちばん大きい音が −1.0 dBFS になるよう、クリップの音量（AudioShape.gain）を決めます。音量の範囲（−60〜+12 dB）に収め、収まらなかったら知らせます。無音のクリップは何もせず知らせます。クリップの音量はテイクぜんぶで共有なので、表示中のテイクで決めます。ステップ名「ノーマライズ」。
  3. 逆にする：元のファイルは変えません。表示中のテイクが使っている範囲を逆にした新しいファイルを作り、そのテイクの代わりに、新しいテイク（新しい ID）を同じ場所に置きます。ほかのテイクはそのまま。フェードと音量はそのまま。もう一度かけると、また新しいファイルができます（元に戻すのは取り消しで）。ステップ名「逆にする」。
  4. 「曲のテンポについていく」がオンのクリップを逆にするとき：元の音のテンポが1つ（途中で変わらない）なら、そのまま引き継ぎます。途中で変わるものなら、ついていくのをオフにして置き、知らせます。
  5. ファイルを作るのは裏の仕事（keeper のスレッド）で、できてから1ステップにします。

約束と作り

  • 約束：NormalizeClips{clips}、ReverseClips{clips}、ステップ名2つ。
  • いちばん大きい音は、ピークのファイル（core/peaks.rs。5段）のいちばん細かい段で足りるか確かめます。足りなければファイルを読みます。
  • 新しいファイルは、作業の場所へ書き、AudioStore と PcmStore に知らせ、ピークを作ります（A7 と同じ道）。画面 Arrange.svelte L1409-1411 の menuRow(..., false, ...) を有効に。

テスト

  • ノーマライズのあとのピークが −1.0 dBFS（±0.1）。逆を2回で元の音と同じ。元のファイルの sha256 が変わらないこと。取り消し。

M2 「音が大きすぎます」のお知らせ

  4. 見つけたら、ステータスラインに「音が大きすぎます。リミッターがずっと 6 dB おさえています」（B では「音が大きすぎます。マスターが 2.1 dB 越えています」）と、ボタン「全部のトラックを 6 dB 下げる」と「閉じる」。数は、A はおさえている量の平均、B は越えた量の最大を、切り上げて 1〜12 に収めたもの。

  • コア：いくつもの音量を1ステップで変えるのは、1つの Doc の上で変更をつないで1つの Edit にします（ai_set_effect_params と同じやり方）。レーンの点は automation.rs の move_points の値の方を使います。画面 StatusLine.svelte。

テスト

M7 歌の音程を寄せる

ふるまい

  1. 右のパネル「選んだクリップ」（音のクリップ）に行「音程を寄せる」：強さ 0〜100 %（はじめ 0 ＝ かけない）と、寄せる先のスケールの表示（「C メジャー」）、ボタン「いまのスケールにする」。
  2. 強さを 0 より上にしたとき、そのときの曲のスケール（ピアノロールのスケール。P1 の9種類）を、クリップが覚えます。あとで曲のスケールを変えても、クリップは変わりません。「いまのスケールにする」で覚え直します。
  3. 音の高さを調べ、声が出ている所を、スケールのいちばん近い音へ「ずれ × 強さ」だけ寄せます。寄せ方は 50 ms でなめらかに。声でない所（息、子音、無音）は変えません。
  4. クリップの移調（±12 半音）、セント、フォルマントを保つ、テンポについていく、と一緒に効きます。
  5. 作るのは裏の仕事で、今のストレッチと同じ流れです（変えてから 300 ms 後に作り始め、できたら 10 ms 重ねて入れ替え、進み具合の表示）。離したとき1ステップ（クリップの形を変える今の道）。
  6. 和音や伴奏の入った音では、結果はあてになりません。ツールチップに「ひとりの声や、音が1つずつの楽器に使えます」。

約束と作り

  • モデル：AudioShape に tune: Option<Tune{root, mode, strength}>（#[serde(default)]）。約束：クリップの形を変える意図（SetClipField）に欄を足す。
  • 高さを調べる処理は、今どこにもありません。crates/meloet-stretch（か meloet-sound）に自作します。YIN（de Cheveigné と Kawahara、2002）か McLeod の方法（McLeod と Wyvill、2005）。クレートは使いません（古いか、ライセンスが未確認）。範囲は 70〜1000 Hz、10 ms きざみ、左右をまぜた音で。
  • 高さを動かすのは今のストレッチ（Signalsmith）です。今の render（render.rs）は1回の作りで移調が1つに決まっています。短いかたまり（256〜512 フレーム）ごとに set_transpose_semitones を変えられる形を足します。C++ と unsafe は meloet-stretch の中だけ。vendor/ のファイルは変えません。
  • 作ったファイルの鍵（made.rs の MadeKey）に、スケール、強さ、調べ方の版を入れます。強さ 0（tune が None）のときは、今の道をそのまま通ります。

テストと受け入れ

  • 作った信号で：スケールの音から 30 セントずれたのこぎり波の長い音 → 強さ 100 で、ずれの中央値が 10 セント未満。強さ 50 で約半分。ノイズだけの音は変わらない。強さ 0 は今の出力と同じ。
  • stretch_app.py kept（作り直しが起きないこと）、stretch_app.py prepare（作る速さ。今の数と並べる）。
  • 音の質は耳で決めます。リードは、歌の録音（なければ、内蔵の音で作った単旋律）で、かける前と後のファイルを target/ に書き出し、場所を持ち主に知らせます。ひどい音（ロボットの声、プツプツ）なら、行を無効で出したままにして統合し、報告します。

F1 書き出しの音の大きさ

ふるまい

  1. 「書き出す前のたしかめ」に行を足します：「曲ぜんたいの大きさ −18.6 LUFS ・ トゥルーピーク −3.2 dBTP」。今の「いちばん大きい所」と音割れの行は残します。
  2. 新しい行「音の大きさ」：「そのまま」（はじめ）と「公開先に合わせる」。右に「−14 LUFS ・ −1 dBTP」。
  3. 「公開先に合わせる」のとき、書き出す音ぜんたいに同じ大きさをかけます：かける量 = −14 − 測った LUFS。ただし、トゥルーピークが −1 dBTP を越えない所まで。小さくする方向にも働きます。リミッターはかけません。
  4. たしかめの下に結果を1行：「合わせると 4.6 dB 大きくなります」。上限で止まるときは「−1 dBTP を越えないよう、−15.2 LUFS になります」。
  5. 無音に近い曲（LUFS が測れない、または −70 より下）と、範囲が「トラックごと」のときは、「公開先に合わせる」は無効（トラックごとは、あとでまぜるためのものなので、大きさを変えません）。

約束と作り

  • LUFS の計算はもうあります（export/analysis.rs。job.measure が立っているときだけ。今は AI 連携だけが立てる）。ダイアログの仕事でも立てます。

  • 画面：export/ExportDialog.svelte、exportText.ts の checkLines。AI 連携の書き出しの道具は「そのまま」のまま。

F2 MP3 の書き出しと曲の情報

ふるまい

  1. 形に「mp3」を足します（wav、flac、mp3）。「くわしく」は、mp3 のとき「ビット」の代わりに「ビットレート」：128 / 192 / 256 / 320 kbps（はじめ 192。いつも一定のビットレート）。サンプルレートは 44100 と 48000 だけ。いつもステレオ。
  2. 「くわしく」に「曲の情報」：題名（はじめは曲の名前）、作者（PC の設定に覚える）、絵（「えらぶ…」。png か jpg、5 MB まで）。wav では絵は入れられないので、絵の行は無効で出します。
  3. トラックごとの書き出しでは、題名を「曲の名前 - トラックの名前」にします。

約束と作り

  • rusty_mp3（Apache-2.0、依存なし、C なし。=1.2.2 で固定。固定する前に、クレートの中の LICENSE を読む）。使い方：Mp3Encoder::new(Mp3EncoderConfig{bitrate_kbps, vbr_quality: None})、push_pcm_f32(&interleaved, 2, sample_rate)、最後に finish() してから next_packet() を Eof まで回す。最初のフレーム（長さと頭の遅れの情報）は finish() のあとで確定するので、もう書いてあるなら lame_tag_frame() でファイルの頭を上書きします。README は push_pcm_i16 と書いていますが、ソースは push_pcm_s16 です。ソースを読んで確かめます。
  • export/sink.rs に AudioSink を実装した Mp3Sink を足し、create() の match に足します。渡す前に ±1 に収めます（このクレートは 8 倍まで通します）。ディザはかけません。
  • 約束：ExportFormat::Mp3（ALL、extension()、bits_choices() は空）、ExportDialogView に mp3_kbps と選べる値、曲の情報の3つ、ExportChange。ビットの型（RecordFormat）にビットレートの居場所はないので、別の欄にします。
  • 曲の情報：lofty（MIT か Apache-2.0。=0.25.5）。書き終えて場所へ移す前に書きます。mp3 は ID3v2、flac は Vorbis コメントと絵、wav は RIFF INFO（題名と作者だけ）。保存の関数の正確な形は、クレートの examples/tag_writer.rs を読みます（未確認）。絵を選ぶのは pcwindow.rs に絵のファイルを選ぶ種類を足します。
  • 網羅の所：crates/meloet-ai/src/tools/files.rs の FormatArg、fake.ts、ExportDialog.svelte の FORMAT_NAMES（鍵がないと型の検査で落ちます）。文書：architecture 22-11、7-readings.md の C-11 の行（今回の決定で上書き）、NOTICE。

受け入れ条件（満たさなければ MP3 は出さない）

  1. 44100 と 48000 のステレオで、実際の曲の書き出しを MP3 にし、symphonia（もう入っている）で読み戻して、長さが元と同じ（頭の遅れと終わりの詰め物を引いて ±1152 サンプル）。
  2. 読み戻した音と元の音の差が、192 kbps で元より 20 dB 以上小さい（1 kHz の音とピンクノイズで）。
  3. 無音、1 サンプルだけ、10 分の曲、やめる、で落ちないし、ファイルが壊れない。
  4. リードが内蔵の音の曲を 192 kbps で書き出したファイルを target/ に置き、持ち主が耳で確かめられるようにする。

1〜3 のどれかが通らなければ、MP3 のコミットを統合せず、形の一覧に mp3 を出しません（spec 3 の「使えないとき mp3 は出さない」のまま）。曲の情報（lofty）は wav と flac のために残します。通らなかった理由を 7-readings.md と progress.md に書きます。品質は LAME より少し下という作者自身の比べしかありません（独立した比べは見つかっていません）。

D4 英語の表示

いちばん最後に作ります（ほかの機能が文言を足し終えてから）。

ふるまい

  1. 設定に「ことば / Language」：日本語／English。はじめての起動では、PC のことば（LC_ALL、LC_MESSAGES、LANG）が ja で始まれば日本語、ちがえば英語。
  2. 切り替えると、画面を読み込み直します（今の「つなぎ直す」の道。ウィンドウも音も曲もそのまま）。カウントイン中と録音中は切り替えられません。
  3. 英語になるもの：画面の文言ぜんぶ、ステップの名前、用語のツールチップ、ファイルを選ぶ窓の題、新しい曲と新しいトラックのはじめの名前（作るときのことばで決まる。あとから変わらない）、歌のトラックのはじめの名前。
  4. 変えないもの：曲のフォルダの中の名前（音、work/音。ファイルの互換のため）、もうある曲の中の名前、ログ、AI 連携が返す文。

作り

  • t() は決まった表を引くだけで、変わったことを画面に伝える仕組みがありません（90 のファイルが text/ja から読んでいます）。だから、最初の描画の前にことばを決め、変えるときは読み込み直す作りにします。
  • ui/src/text/index.ts を作り、t()、fill()、用語、ステップ名、つなぎの文字（TERM_SEPARATOR、STATUS_JOIN、LIST_COMMA）をここから出します。ja.ts は表（正。出どころつき）のまま。en.ts は同じ鍵の表（出どころなし）。読んでいる所の書き換え（"../../text/ja" → "../../text"）は機械的なので meloet-light に。
  • ことばは、あいさつの返事（HelloReply）に足して受け取り、main.ts で部品を置く前に決めます。index.html の lang もそこで。設定と意図は、テーマ（SetTheme、settings.rs の theme）を見本に：SetLanguage{language} → 保存 → 画面が読み込み直す。
  • 用語のツールチップは日本語の言葉そのもので引いています（use:term={"バッファ"}。65 か所）。鍵は日本語のままにし、英語の表は「日本語の言葉 → 英語の言葉と説明」にします。
  • 数の入る文：英語は1つとそれ以外で形が変わります。英語の表の項目は、1つの文か、（1つのとき、それ以外）の組を持てるようにします。日本語の側は変えません。文字をつないで作っている所（format.ts など）は、穴のある文に直します。
  • Rust の中の日本語：pcwindow.rs の窓の題、meloet-model の song.rs（「はじめての曲」「ピアノ」）、audio.rs（「歌」）、instrument.rs の track_name()。作るときに、ことばを引数で渡します。
  • 訳し方：docs/spec/glossary.md の英語の言葉に合わせる。文の頭だけ大文字。キーの名前はキーボードの刻印のとおり。日本語より長くなって入らない所は、言い換えて収める（幅を広げない）。
