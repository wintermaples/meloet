## 理由のさがし（直していない）

WebKitWebProcess の主スレッドの CPU（15 秒、1920×1080、`/proc/<pid>/task/*/stat` を読んだ）:

| 状態 | WebKitWebProcess 主スレッド | meloet 主スレッド（UI） |
|---|---|---|
| 止まっている | 5.8 % | 1.2 % |
| 再生中 | 16.3 % | 3.8 % |
| 録音中 | 22.4 % | 4.7 % |

- 録音中は、web の主スレッドが 1 秒の 22 % ふさがっている。1 フレーム（16.7 ms）のうち約 3.7 ms。鍵の知らせが、そのふさがっている間に来ると待たされる。遅れの大きさ（4〜7 ms）とも合う。
- 読んだコード（`ui/src/components/Arrange.svelte` の `frame()` と `moveTail()`、`ui/src/components/Transport.svelte` の rAF）で、動いている間に毎フレームしていること:
  - `moveTail`: 録音中のクリップのしっぽの `left`・`top`・`width`・`height` を毎フレーム書く（レイアウトのやりなおし）。その周の**全部のノート**から `G.liveShapes` と `G.paintClip` で四角を作りなおし、`tailSlot.update` で WebGL の区画を汚す（→ その区画の `getBoundingClientRect` と描きなおし）。ノートが増えるほど 1 フレームの仕事が増える。
  - `placeLines`: 再生線の `transform` を毎フレーム書く。
  - `Transport.svelte`: 止まっているときも rAF で `frame` を毎フレーム増やし、位置と時計の文字を作りなおしている。
- どの面を何回描いたかは、`ui/src/gl/engine.ts` の `stats`（frames、draws）が外から読めないので、数えていない。数えるには、画面に計測の口（`MELOET_MEASURE_DIR` があるとき、`stats` を `measureReport` で書く）を足す必要がある。`ui/` は今回さわれないので、棟梁と相談。
- 案（直す前に相談）: (1) しっぽの四角を、増えたノートの分だけ足す形にする（毎フレーム全部作りなおさない）。(2) しっぽの大きさは小節が変わるときだけ書く。(3) 止まっているときは Transport の rAF を止める。
