# 第 5 回 区切り2 の測定: SF2 を読んで鳴らす所（2026-11-19）

`crates/meloet-sound` の SF2 の読み手（`src/sf2/`）と、広げたサンプルを鳴らす係（`src/sampler/shape.rs`）を、FluidR3_GM.sf2 で FluidSynth 2.4.8（この PC の `/usr/bin/fluidsynth`、別のプロセス）とくらべた。重さと読みこみの時間も測った。

## ひとめで

- **FluidSynth とほぼ同じに鳴る**。15 のプリセットのうち 14 で、0.25 秒ごとの大きさのちがいが 0.3〜0.9 dB、明るさの重心のちがいが 2.2 % 以内。どれも meloet が 0.2〜0.4 dB 大きいだけ（下の「0.4 dB」）。
- 残る 1 つ（Polysynth）は、はじめの 0.3 秒ほどで 1〜2 dB ちがう。同じサンプルを 2 枚重ねる音色で、重なりの位相がずれるためと見ている（確かめていない。下の「Polysynth」）。
- 調べるうちに FluidSynth の動きで分かった事が 3 つ（どれも測った数から。ソースは読んでいない）。
  1. フィルターの利得 1/√Q は、フィルターを使わないゾーンにもかかる（Q が 0 でも +1.5 dB）。合わせた。
  2. カットオフが開いたまま（13500 cent）でも Q があればフィルターは回る（ハイハットが 3 dB 小さくなる）。合わせた。
  3. ノートは 64 こまのブロックの頭で始まる。くらべる道具（`sf2_listen`）は、meloet にも同じこまでノートを渡す。そうしないと、同じ鍵を続けて弾く所（ギターのストローク、ハイハット）で 2〜3 dB ちがって見える。
- 重さ（48 kHz、256 こま、release）: 64 声でフィルターと LFO とエンベロープを全部動かして 1 ブロックの 2.9 %（今の包みの 64 声は 1.5〜1.8 % で、変わっていない）。SF2 の同時の声は 128 にした。128 声を全部動かして 5.8 %。
- 読みこみ: FluidR3（142 MiB）をひらくのに 0.2 ms（表だけ読む）。プリセット 1 つは 0.0〜4.5 ms、メモリは 0.0〜10.6 MiB（そのプリセットのサンプルだけ）。ファイルがディスクのキャッシュにある時の数。
- 今の包みの音色: `render_pack` の 72 個の WAV が、直す前と 1 ビットも変わらない（sha256 が同じ）。

−90 dBFS より下のちがい（piano の −93.1 と −104.2 など）は、FluidSynth が 16 bit に書くときのディザの床で、音のちがいではない。

### ちがいの中身

- **0.4 dB**: どのプリセットでも、どの強さ（20 ・ 64 ・ 100 ・ 127）でも、CC7 がいくつ（30 ・ 64 ・ 100 ・ 127）でも、meloet が同じだけ大きい。フィルターのあるなしにもよらない。**見立て**（確かさ C。測った数と合うが、ソースで確かめていない）: FluidSynth は強さ ・ CC7 ・ CC11 を 127 ではなく 128 で割っている。3 つぶんで (127/128)⁶ = −0.41 dB。meloet は依頼どおり `(v/127)²` のまま。聞いて分かる差ではない。
- **Polysynth**: 同じサンプル（Halo Pad）を 2 セントずらして 2 枚重ね、片方にだけ 20 ms の音の高さのエンベロープ（−752 cent）がかかる音色。2 枚の重なりの位相が、エンベロープを刻む細かさ（meloet は 32 こま、FluidSynth は 64 こま）のちがいでずれ、足した大きさが 1〜2 dB 変わる、と見ている（確かさ C）。おさえた 1 音で差の向きが時間で入れかわる（+1.4 → +0.9 → −1.5 dB）のは、2 セントのうなりと合う。モジュレーションのエンベロープのアタックを「まっすぐ」に変えても差は変わらなかったので、アタックの形のせいではない。
- **重心が 1〜3 % 低い物**（vibraphone、synth-pad、fretless-bass）: 理由は調べていない。
