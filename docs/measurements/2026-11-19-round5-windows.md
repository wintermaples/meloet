# 第 5 回 区切り3: プラグインの窓とパラメータで測った数

測った日 2026-11-19 〜 20（meloet-hard）。道具は `crates/meloet-plughost/tests/real_windows.rs` と `tests/windows.rs`。

```bash
source ~/.config/meloet-agent/env.sh; export DISPLAY=:0
cargo test -p meloet-plughost --test real_windows -- --ignored --nocapture --test-threads=1
MELOET_WINDOW_ROUNDS=200 cargo test -p meloet-plughost --test real_windows -- --ignored --nocapture --test-threads=1 many_times
cargo test -p meloet-plughost --test windows -- --include-ignored --nocapture
```

## 条件

- AMD Ryzen 7 7700、Linux 7.0.0-43、Ubuntu 26.04（GNOME、Wayland。窓は Xwayland の `:0`）。`meloet-agent`（`audio` グループ）。`env.sh` は `DISPLAY` を決めていないので、道具の前に `DISPLAY=:0` を足した（ファイルのソケットは別ユーザーに書けないが、libxcb は抽象ソケットで入る）。
- 窓はヤチヨさんの画面に本当に出した。音の出口にはつないでいない（試験が 5.333 ms ごとにブロックを頼む。試験のスレッドはリアルタイムではない、plughost の音のスレッドは SCHED_FIFO）。
- ヤチヨさんの meloet は動いていなかった。**ほかの係が 2 人、同じ PC でビルドと試験をしていた**（load average 0.1〜5.8）。時間の数はにごっている。メモリの数は、にごりにくい。
- ビルドは debug（下の表）。release で同じ道具を走らせた数は、いちばん下。
- キーボードの出入り（FocusIn ・ Out）は、試験が X に `SetInputFocus` を送って作った。つまみのドラッグは、試験がプラグインの窓に作り物のボタンと動きの出来事を `SendEvent` で送って作った（本物のポインタは動かさない）。**人が本当にマウスでさわった時の動きは、見ていない。**

## 1. 窓の型、ひらく時間、大きさ

「ひらく」= `OpenEditor` を送ってから `EditorOpened`（デスクトップが窓を画面に出した）まで。1 回目 / 2 回目 / 3 回目（同じプロセスの同じプラグイン）。「閉じる」= `CloseEditor` の返事まで。`OpenEditor` の返事そのものは、どれも 100 ms より前（試験が見はっている。偽物では 1 ms ほど）。

| プラグイン | 型 | ひらく ms | 大きさ | 画面より大きい | 閉じる ms | 入った ・ 出た |
|---|---|---|---|---|---|---|
| Surge XT（VST3） | ひらける | 84〜100 / 95〜99 / 87〜89 | 1597×995 | いいえ | 12.9〜13.6 | 来た |
| Surge XT（LV2、X11UI） | ひらける | 118 / 98 / 89 | 1597×995 | いいえ | 10.9 | 来た |
| ZamComp（VST3） | ひらける | 77 / 12 / 15 | 800×107 | いいえ | 2.0 | 来た |
| ZamComp（LV2、X11UI） | ひらける | 111〜199 / 12〜18 / 13〜15 | 800×107 | いいえ | 2.4〜3.3 | 来た |
| LSP Compressor Stereo（VST3） | ひらける | 126〜141 / 119〜138 / 121〜142 | 944×548 | いいえ | 28.3〜28.8 | 来た |
| LSP Compressor Stereo（LV2、X11UI） | ひらける | 172 / 136 / 121 | 944×548 | いいえ | 31.7 | 来た |
| Dragonfly Hall Reverb（LV2、X11UI） | ひらける | 135 / 13 / 16 | 920×345 | いいえ | 1.9 | 来た |
| abGate（LV2、GtkUI ＋ Qt5UI） | まだひらけない | — | — | — | — | — |
| swh amp（LV2） | 窓を持たない | — | — | — | — | — |

- 7 つとも、1 回目でひらいた。ひらいたまま音を鳴らし、meloet から値を決め、閉じ、もう一度ひらき、× で閉じ（`EditorClosed` が来る）、3 回目をひらいたまま外しても、プロセスは落ちなかった（最後は `Quit` で終わりコード 0）。
- **0.2 秒をこえたのは無かった**（いちばん長いのは ZamComp の LV2 の 1 回目 199 ms。GL のライブラリを読む分）。PC がいそがしければ、こえる。
- 「ひらけない」物に `OpenEditor` を送ると、`Opening` のあと `EditorFailed`（"no window meloet can open"）。プラグインはそのまま鳴る。
- Dragonfly は大きさを言ってこないが、中に作った窓の大きさ（920×345）で、ひらいた時から合っていた。

## 2. パラメータの一覧

| プラグイン | 数 | 一覧を取る ms | なめらか / 段 / オン ・ オフ | わからない値 | グループ |
|---|---|---|---|---|---|
| Surge XT（VST3） | 2854 | 33 | 2854 / 0 / 0 | 0 | 14 ＋ グループなし 2080 |
| Surge XT（LV2） | 775 | 8.3 | 775 / 0 / 0 | 774 | 14 ＋ グループなし 1 |
| ZamComp（VST3 ・ LV2） | 8 | 0.2 | 7 / 0 / 1 | 0 | なし |
| LSP Compressor Stereo（VST3 ・ LV2） | 47 | 0.8〜1.0 | 23 / 7 / 17 | 0 | なし |
| Dragonfly Hall Reverb（LV2） | 18 | 0.3 | 18 / 0 / 0 | 0 | なし |
| abGate（LV2） | 6 | — | — | 0 | なし |
| swh amp（LV2） | 1 | — | — | 0 | なし |

- Surge XT のグループ 14 個は、VST3 も LV2 も同じ: A Common、A Envelopes、A Filters、A LFOs、A Mixer、A Oscillators、B …（同じ 6 つ）、Global & FX、Macros。どちらも、プラグインは「Root」という段 1 つの下にこの 14 個をぶらさげている。Root は根として読んだ（20-13）。
- **Surge XT の VST3 の「グループなし 2080 個」は、ぜんぶ `MIDI CC 0|0` 〜 `MIDI CC 15|129`**（16 チャンネル × 130 個。JUCE が MIDI のコントローラの代わりに立てるパラメータ）。プラグインは隠す印をつけていないので、頼まれた決まり（隠す印 ・ 読むだけ ・ バイパスは出さない）では一覧に入る。出さないなら、`IMidiMapping` に聞けば見分けられる（棟梁への質問）。
- Surge XT は、VST3 でも段やオン ・ オフを言わない（全部 `stepCount` 0）。LV2 は全部 `atom:Float`。なので Surge XT の行は、どちらも全部「なめらか」になる。
- Surge XT の LV2 は、775 個のうち 774 個が「わからない」で始まる（わかる 1 個は control のポート）。meloet が決めた値と、窓で動かした値は、そこから「わかる」。
- LSP の段の文字の例: 「Split sidechain source」= Left/Right、Right/Left、Mid/Side、Side/Mid、Min、Max。

## 3. 値の文字と、文字 → 値

| プラグイン | パラメータ | 0 ・ 0.5 ・ 1 の文字 | まん中の文字を読ませる | 「99999999」を読ませる |
|---|---|---|---|---|
| ZamComp（LV2） | Attack | 0.10 ms ・ 50.05 ms ・ 100.00 ms | 0.5000、はみ出しなし | 1.0、はみ出した、「100.00 ms」 |
| ZamComp（VST3） | Attack | 0.100000 ms ・ 50.049999 ms ・ 100.000000 ms | 0.5、はみ出しなし | 1.0、はみ出した、「100.000000 ms」 |
| LSP Compressor（VST3） | Input to Link mix | -inf dB ・ -30.02 dB ・ 20.00 dB | 0.50005、はみ出しなし | 1.0、はみ出した、「20.00 dB」 |
| LSP Compressor（LV2） | Input to Link mix | 0.00 G ・ 5.00 G ・ 10.00 G | 0.5、はみ出しなし | 1.0、はみ出した、「10.00 G」 |
| Dragonfly（LV2） | Dry Level | 0.00 % ・ 50.00 % ・ 100.00 % | 0.5、はみ出しなし | 1.0、はみ出した、「100.00 %」 |
| Surge XT（LV2） | A Osc Drift | 0.00 ・ 0.50 ・ 1.00 | 0.5、はみ出しなし | 1.0、はみ出した、「1.00」 |

- VST3 は 3 つとも `getParamValueByString` が答えた。LSP の VST3 は、はみ出した数をだまって 1.0 にするので、「はみ出した」は打った数と端の文字の数（20.00）をくらべて出している。
- LV2 の文字はプラグインではなく plughost が作る（数 ＋ 単位）。LSP の LV2 は単位の記号を「G」と書いている（同じパラメータを VST3 は dB で出す）。LV2 と VST3 で文字がちがうのは、そのため。
- Surge XT の LV2 は、TTL に単位も範囲の意味もなく、全部 0〜1 の数にしか見えない（「A Osc Drift」が 0.00〜1.00）。VST3 なら Surge XT 自身の文字が出る。

## 5. 窓を何十回も

1 回 = ひらく → ひらいたまま 60 ブロック（0.32 秒）鳴らす → 閉じる → 4 ブロック。ひらいている途中も、ブロックを頼みつづけた。「遅れ」= 返事が 1 ブロック（5.333 ms）より遅かったブロックの数。

### 50 回（debug、load average 2〜4）

| | 窓なし 3000 ブロック | ひらく ms（最小 / まん中 / 最大） | ひらいたまま 3000 ブロック | ひらく ・ 閉じる間 |
|---|---|---|---|---|
| Surge XT（VST3） | いちばん長い返事 1.76 ms、遅れ 0 | 84 / 96 / 118 | 0.68 ms、遅れ 0 | 1169 ブロック、0.66 ms、遅れ 0 |
| ZamComp（LV2） | 0.07 ms、遅れ 0 | 10 / 14 / 122 | 0.13 ms、遅れ 0 | 375 ブロック、0.12 ms、遅れ 0 |

- その前に、もう 1 回走らせた時（load average 5.8、ほかの係のビルド中。ひらく間のブロックは、まだ頼んでいなかった）は、ひらいたままの 3000 ブロックに遅れが 1 つずつあった（Surge XT 12.15 ms、ZamComp 6.33 ms）。静かな PC で、もう一度見る価値がある。

## 6. 音のスレッドの見はり

- `cargo test -p meloet-plughost --bin meloet-plughost -- --include-ignored`: 本物の 6 つ（Surge XT ・ LSP ・ ZamComp の VST3 と LV2）と、**窓がひらいている形の LV2 2 つ**（Surge XT ・ LSP。窓からのメッセージを受け、control の出力とメッセージを窓へ写す）で、音のスレッドの meloet のコードのメモリ確保は 0。

## わかっていない事

- 人が本物のマウスとキーボードでさわった時の、入った ・ 出たの知らせ（GNOME が窓にキーボードをわたす順、プラグインのメニューやダイアログにいる間）。しかけは作ったが、作り物の出来事でしか見ていない。
- Surge XT の VST3 は、ここでは 1597×995 でひらいた。「画面より大きい」が本当になる画面では、見ていない。
- 窓の中で人が大きさを変える（VST3 の `canResize`）は、動かして見ていない。
- 静かな PC での数。`audio` グループでない PC（rtkit だけ）。
- 窓のスレッドが固まるプラグイン（音は続くはずだが、Hosts は次の頼み事が 5 秒返らない時にプロセスごと止める。固まった事だけを知らせる道はない）。
