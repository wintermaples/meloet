## 1. 字が足りるか（`k7f3-fontcheck.py` ・ `k7f3-fontmiss.py`、fontTools 4.68）

`ui/src/text/ja.ts`、`ui/src/`（`generated/` をのぞく `.ts` ・ `.svelte` ・ `.css` ・ `.json`）、`crates/` の `.rs`（試験をのぞく）に出てくる字 745 個を、太さごとに、いまの形で使われる切れはし（CSS の決まりどおり、範囲が合う `@font-face` のうち最後の物）と、切っていない woff2 の cmap でくらべた。太さ 400 ・ 500 ・ 600 で答えは同じ。

- 両方にある字: 724 個。**輪郭も送り幅も 724 個とも同じ**。
- **切ってある形にだけある字（13 個）**: 画面の文と部品で使う物は `∞`（`−∞ dB`）、`→`、`■`（「■ 停止中」）、`●`、`♪`（「♪ ためし弾き中」）。コメントだけで使う物は `←` `√` と罫線（`─ └ ┘ ┬ ═ ▲`）。
- どちらにもない字（8 個。いまも PC の書体で出ている）: `▶ ▸ ▾ ◂ ◀ π ≈ ↔`。
- 字の数: 切れはしを合わせると 8221 字、切っていない woff2 は 6882 字。**1340 字がへる**（109 個の切れはしに散らばっている）: 漢字 390（`吞 噓 增 俠` など）、康熙部首 210、罫線 87、半角カナ 64（`ｱ` 〜 `ﾟ`）、丸数字 ・ かっこ数字、キリル 66、`★ ☆ ○ ◎ □ △ ▽ ◆ ◇`、`♭ ♯ ♪`、矢印（`← → ⇒ ⇔`）、`※ ‰ № ℃`、`― ‐ ‖ † ‡ ‥`、`∞ √ ≠ ≦ ≧` など。ひらがな ・ カタカナ ・ ASCII はぜんぶある。
- 逆に、切っていない woff2 にだけある字は 1 つ（U+0303）。
- 版の表: 切れはし（latin、119）と切っていない woff2 で、`head`（unitsPerEm 1000、fontRevision 1.001）、`hhea`（ascent 1060、descent −440、lineGap 0）、`OS/2`（typo 880 / −120、win 1060 / 440、xHeight 541、capHeight 733）、`post` の下線、`name`（`IBM;IBMPlexSansJP-Regular;1.001;2021`、Version 1.001）、表の種類（`cvt ` ・ `fpgm` ・ `prep` ・ `gasp` も）がみな同じ。同じもとの書体。

**B では、人が打った名前（トラック、クリップ、マーカー、曲）とプラグインの名前に、へった 1340 字のどれかがあると、その字だけ PC の書体になる。** C は画面の文の 6 字だけを戻した形で、人が打つ字は B と同じ。

### なぜちがうか（`k7f3-hint.py`、freetype-py、FreeType 2.13.2）

同じ字（68 字 × 7 つの大きさ = 476 通り）を、いまの形で使われる切れはしと、切っていない woff2 から、FreeType でじかに描いてくらべた。

|---|---|
| なし | 0 / 476 |

## 気になった事（製品は直していない）

### 1. こんだ PC で 1 回、鳴らしたクリップが 256 こま（1 quantum）おそかった

- `target/k7f3/m/position-latency-A/`（11:34、Chrome が 180 個動いていた。load 4〜6）の前半。1 回めは −256.0、**2 回めは 17 クリックとも −256.0**（ふつうは −512.0）。
- 録った wav（`state/work/音/歌 2 9.wav`）を見た（`k7f3-clicks.py`）: 拍 1〜16 に、−256 こまに、ふつうの大きさ（0.13、アクセント 0.17）のカチッが 1 つずつ。−512 には何もない。拍 0 はふつうの回と同じ（−256 に 0.087）。
- 読み: メトロノームが鳴りっぱなしなら、拍 0 もふつうの大きさ（0.17）で、クリップのカチッ（−512）も重なって出るはず。どちらもない。**クリップが、まる 1 ブロックおそく鳴った**と読む（推しはかり。エンジンの中は見ていない）。
- 起きた数: こんだ PC の 7 回に 1 回、静かな PC の 8 回に 0 回。meloet の標準エラーには何も出ていない。
- 生の物は残してある（`position-latency-A/` の wav 2 つと `recovery.json`、ふつうの回は `position-A-busy-1/` など）。

### 2. メトロノームを切ったあとの録音の頭に、半分の大きさのカチッが 1 つ出る

- 2 回めの録音（メトロノームは切ってある）の拍 0 に、−256 こま ・ 0.087 のカチッ（15 回の録音ぜんぶ）。場所はメトロノームのカチッと同じ（−256。鳴らしたクリップなら −512）。
- **推しはかり**: 止まっている間に切ったメトロノームが、次に動きだした最初のブロックで 20 ms かけて消える（最初の 1 つが半分の大きさで鳴る）。人の耳には、切ったはずのメトロノームが 1 回だけ小さく鳴って聞こえるはず。確かめていない（エンジンのコードは読んでいない）。

### 3. `font_start.py` で見えた事

## 書体を変える事への、係の意見

**B はすすめない。C は「画素が変わってよい」とオーナーさんが言うなら入れる値打ちがある。言わないなら、いまのまま。**

- 得る物（C）: 再生中のコマが、どの曲でも 2 ms 軽い（6.9 → 4.9 ms）。歌 192 個がぜんぶ見える所が 17.7 → 13.6 ms（16.7 ms の中に入る）。ピアノロールのドラッグの答えが 32 → 28 ms。WebKitWebProcess が 12 MB 小さい。`dist` が 3 MB 小さい。
- 払う物（C）:
  1. **見た目が変わる**。文字のある所ぜんぶで、いくつかの字の線が 1 画素ぶん変わる（ヒンティングが slight の PC。Ubuntu のはじめの値）。字の位置と幅は変わらない。これは「仕様書にもモックにもない見た目」ではないが、決まりの「見た目が 1 画素も変わらないか」には通らない。
  2. **人が打つ字のうち 1334 字が PC の書体になる**（半角カナ、丸数字、★ ☆ ♭ ♯、まれな漢字 390）。曲やトラックの名前に `♯` や `①` を使う人はいそう。
  3. 最初の絵が 50 ms おそい。
  4. 記号の一覧を手で持つ（見はりの試験がいる）。
- B は、C の払う物に加えて、画面の文の `● ■ −∞ → ♪` が PC の書体になる（● の大きさが変わる）。C との速さの差はない。
- **ためしていない別の道**: 切ってある形のまま、`@font-face` の数だけへらす（画面の文で使う字の入った切れはしだけを先に入れ、ほかは、その字が出たときに足す）。起動した時に読めていた切れはしは 3 つの太さで 63 個（太さ 1 つに 20 個ほど）なので、123 → 20 ほどにできる見こみ。切れはしが同じなら自動ヒンティングも同じなので、**画素は変わらないはず**。速さは、C（7 個）と B（1 個）の差がゆれの中だったので、20 個なら 2 ms のうち 1.7 ms ほど取れる見こみ（どちらも推しはかり。作っても測ってもいない）。`@font-face` を自分で書く CSS か `FontFace` がいる。
