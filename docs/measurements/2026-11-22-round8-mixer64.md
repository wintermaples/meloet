## わけ

1. 直す前に、`webkit-stacks.sh`（25 ms ごと、200 回）: 85 % が `getBoundingClientRect` からのレイアウトで、`RenderBlock::simplifiedLayout` → `layoutOutOfFlowBox` → `RenderFlexibleBox::layoutBlock` → `applyStretchAlignmentToFlexItem`（63 %）。flex の行が、伸ばした子をまるごとレイアウトしなおしていた。
2. ストリップ（`mixer/Strip.svelte`）は `content-visibility: auto`（横に送った外の 40 本ぶんの中を飛ばす）。`8edba43` から、帯が音量を動かすトラックの値の字は、見えていないストリップの分も毎コマ書いていた（`autoState.svelte.ts` の `writeMixer` は帯の動くトラックぜんぶ、`Strip.svelte` の `gainShown` と `askLive` も見えているかを見ない）。
3. ためし: ページに `.strip{content-visibility:visible !important}` を入れる（`MELOET_EVAL`）と、`measureMs` は 204 → 0.29 ms（コマは 37 → 365 / 10 秒。外の 40 本も描くので 1 コマ 40 ms）。中を飛ばしているストリップの中の字を変えると、WebKit がミキサーの行ぜんぶをレイアウトしなおす形と見る（確かさ C: WebKit のコードは読んでいない。呼び出しの列とこのためしから）。
4. 字を書いてはレイアウトを読む、のくり返しではなかった。1 コマのレイアウトは 1 回で、その 1 回が重い。

## 直した形

- `automation/coverIf.ts` に `whenSeen`（1 つの `IntersectionObserver` で、箱が見えているかを知らせる）。
- `mixer/Strip.svelte`: 値の箱 `.gain-box > .value` が見えている間だけ、値の字にいちばん新しい位置を出し（`gainShown`）、`askLive` で四角を頼む。見えていない間は、つまみと同じ値（canvas を描くコマに見せる値。見えていないトラックは見えるまで待つ）のままで、字は変えない。見えると次の知らせから毎コマにもどる。
- 見えているストリップの値の字は、いままでどおり毎コマ（仕様書 3 章、間引かない）。
- 試験: `ui/tests/round8.mixer64.test.ts`（見えている間は 5 コマ続けて字が毎コマ変わる、外に出たら変えず四角の箱もなくなる、もどればまた毎コマ）。

### 64 本が 60 にもどらない分

字を毎コマ変えない形（字はつまみと同じ値、`askLive` なし。測るためだけに作った）では、同じ時に **55.9 ・ 56.4 コマ/秒、busyMs 17.6 ・ 17.5 ms**（第 7 回の 56〜60 の下のはし）。見えている 22 本ほどの字を毎コマ変える分が、1 コマ 3 ms ほど。

その 3 ms がどこかを、ページに CSS を入れて分けた（どれも直したあとのビルド、45 秒、1 回ずつ）:

| ためし | コマ/秒 | busyMs 平均 |
|---|---|---|
| そのまま | 47.3〜49.3 | 20.4〜21.4 |
| 字を描かない（`.in{visibility:hidden}`） | 49.5 | 19.7 |
| 字の箱をなくす（`.in{display:none}`。四角を頼む箱は残る） | 49.7 | 20.2 |
| 「dB」の字を等幅の書体に | 49.6 | 20.0 |
| ミキサーの canvas をかくす | 47.8 | 20.5 |
| 30 本目から先のストリップをなくす | 49.0 | 20.6 |
| 再生の線をなくす | 49.8 | 19.9 |
| 字を書いたあとのレイアウト（`wrote`）をやめる | 47.4 | 22.2 |
| 四角を頼む箱（`askLive`）をなくす | **30.2** | 63.3（ぜんぶを囲む四角） |

- 字そのもの（レイアウト、描く字、書体）でも、canvas でも、外のストリップでもない。JavaScript の分（rAF ＋ 小さな仕事、ページの中で時間を取った）は、字なしより 1 コマ 1 ms 足らず多いだけ。
- のこりは「値の行の四角」（`webkit-damage.sh`: `0 941 1896 27`。見えているストリップの値の行を左右のはしまで 1 つにした四角）を毎コマ描く分と見る（確かさ C）。左右の半分の canvas は 1 コマおきなので、描かない半分の値の行も毎コマ描く。この四角をなくすと、字の小さな四角が 11 個をこえて、ぜんぶを囲む四角になる（上の表の最後の行）。

## 棟梁に出す案（作っていない）

64 本 ・ 帯つきを 56〜60 にもどすには、値の行を毎コマ描く分（3 ms）をけずる要る。どれも仕様書 3 章「毎コマ変える（間引かない）」にかかわるので、決めてもらいたい。

1. 値の字を、つまみと同じく「上の canvas を描くコマ」に変える（左右の半分ごとに 1 コマおき、30 Hz）。値の行の四角は canvas の四角の中に入り、ふえない。どの本数でも同じ形。
2. 1 を、字なしの busyMs が重い時（たとえば見えているストリップが 20 本をこえる時、か、帯の動くトラックが 32 本をこえる時）だけ。
3. 字は毎コマのまま、ほかの所で 3 ms けずる（下の「気づいた事」の書体の所など）。

## 気づいた事（あとの宿題）

- `webkit-stacks.sh` で、どの回もスタックのいちばん上の 10 % が `WebCore::CSSFontAccessor::isLoading`（`FontCascade::isLoadingCustomFonts` → `FontRanges::isLoading` から。字を描くたび）。`@fontsource/ibm-plex-sans-jp` の 400 は `@font-face` が 123（unicode-range ごと）、`ibm-plex-mono` は 5。字を描くたびに 123 の範囲をたどっている形と見る（確かさ C）。ページぜんたいの字を描く重さにかかわるので、書体の読みこみかた（`ui/src/design/fonts.ts`）を見なおす値うちがある。
- 再生の線は、古い位置と新しい位置の 2 本が、トラックの見出しのメーターの四角の上下で切られて、1 コマに 4 つの四角になる。なくしても 1 ms ほど。
