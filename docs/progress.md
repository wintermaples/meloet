## 第 1 回: 土台と、「つないで、光って、鳴る」まで（2026-11-14〜）

### ヤチヨさんに聞いて決めたこと（2026-11-14）

| 問い | 答え |
|---|---|
| 係（.claude/agents/）がこの会話から呼べない | このままの会話で、同じモデルと effort の汎用の係に、係のファイルを最初に読ませて頼む（新しい会話では名前で呼べることを確かめた） |
| 仮の音の名のりかた | 名前は「仮の音」。用語の説明「仮の音 — 本物のピアノの音が入るまでの、かわりの音。」を足す |
| モックにだけある文 | モックの文を一字も変えずに使う。仕様書と食いちがう所は仕様書。どちらにもない場面だけ聞く。使った文は一覧にしてデザインに戻す |
| 出口えらび（流れ 2）を出すとき | 鍵盤が見つかってから（モックのとおり）。音の設定からはいつでもえらべる |
| 今回は本当でないことを言うモックの文（録音待機、録った音がならびます、トラックを追加、録音 R ・ 再生と停止 Space） | 今回は出さない。そこは空ける |
| 「音が出ました」の案内を消すとき | 鍵盤以外の操作（マウスで押す、キーで何かする）で消す。一度消したら、この曲では出さない |
| 覚えた出口が起動したときに見つからない | 「（出口の名前）には、いま何もささっていません。ささると、ここから鳴ります。」と「音の設定をひらく」。ささったら、そのまま鳴らす |
| 状態行の「入口:」 | 鍵盤の本物の名前だけ。鍵盤がないときは「入口: まだ」。マイクは歌の回まで出さない |
| 出口えらびに何をならべるか（同じ装置の中の Route は PC が切りかえ、HDMI は PC の設定で今は使えない） | 全部ならべる。PC の設定を変えずに鳴らせる物だけえらべる。ほかは「使えない」の見た目。理由の文は出さず、デザインに戻す |

### 棟梁が決めたこと（仕様書の読みかた）

| 所 | 決めたこと | 理由 |
|---|---|---|
| 仕様書の文の中の例の値 | 「鍵盤 49」「ヘッドホン」「1024」「256」「53」「13.5」などは、本物の値をうめこむ穴にする。まわりの文は一字も変えない | 「鍵盤の名前も本物をそのまま出す」「バッファは本当に動いている数を出す」の決まりと合わせるため |
| 帯札「ミキサー マスター ○ dB」 | マスターのフェーダーの値（今回は 0.0 dB のまま） | モックの多く（Main、A-Mixer など）がフェーダーの値。流れ 1〜3 だけは音の大きさだった。食いちがい |
| 新しい曲の「テンポ ・ 拍子の変更」 | 0 件 | 仕様書: 帯札は「変更の件数」。モックの「2 件」は新しい曲では食いちがい |
| 鍵盤が 2 台 | 全部聞く。名前は最後にさした物 | 仕様書にない。仮の決め |
