# 進みぐあい

## 第 1 回: 土台と、「つないで、光って、鳴る」まで（2026-11-14）

ブランチ `foundation`。仕様書とモックは `docs/design/` に写してある（2026-11-14 に受けとった版）。

### できたこと

1. 立ちあげると、からっぽのアレンジ（トラック 1「ピアノ」、音源は「仮の音」）。上から、再生まわり、入力計、アレンジ、帯札の行、状態行。右はしに「棚」と「パラメータ」の縦の見出し。
2. 帯（ピアノロール、ミキサー、取り消しの履歴、棚、パラメータ）がひらく・たたむ。中身は空。帯の決まりは本物（`crates/meloet-core/src/layout.rs`）: だれがだれを押しちぢめるか、古い帯の自動のたたみ、入力計 52 ⇔ 24、窓 960 以上はいつも 52、Esc でひとつ戻る、A でアレンジへ。
3. 鍵盤がないときの文面。さした瞬間に本物の名前。立ちあげる前からささっていても出る。ぬくと、その文面。長い名前の決まり（108 → 148、細いとき 176・128、「…」とマウスで全部）。
4. 鍵を押すと入力計の鍵が光る。押している音、ベロシティ、サステイン、ピッチベンド、モジュレーション。音の出口がまだでも光る。
5. 音の出口えらび（流れ 2）: 本物の名前、やさしい言いかえ、ささっているかの印、テスト音、↑ ↓ と Enter。えらんだ出口は覚えて、次からは聞かない。
6. トラック 1「ピアノ」が鳴る（仮の音）。トラックとマスターのメーター。「音が出ました」。音源をさしかえる口（`Instrument`）は本物の形。
7. 状態行に、出口、入口、バッファ（本当に動いている数。頼んだ数とちがえば両方）。固定されているときの文面と、音の設定の奥の案内。
8. 音の設定（Ctrl+,）。おもてで出口をえらびなおせる。奥は見せるだけ（まだ使えない部品は「使えない」）。
9. 拡大率 100・125・150%（Ctrl+Alt+1・2・3）。線（line.hair）は物理 1px のまま。
10. 用語の説明（0.6 秒）と、キーの土台（文字を打っている最中は一文字のキーが効かない）。

ほかに: 係 3 つ（`.claude/agents/`）、`scripts/check-all.sh`（コマンド 1 つで全部の検査）、開発用の環境変数（README）、計測の道具（`tools/measure/`）、見くらべの道具（`tools/design/`）。

### 測った数字（release、1920×1080、仮想の鍵盤で 120 鍵、バッファ 256 で動いている、48000 Hz）

| | 今回 | 検証のとき |
|---|---|---|
| 鍵 → 画面（Rust が受けてから描くまで）p50 / p95 / 最大 | 1.15 / 1.17 / 3.19 ms | 0.28 / 0.84 / 5.2 ms |
| 鍵 → 画面（Rust → JS）p50 / p95 / 最大 | 0.15 / 1.12 / 1.19 ms | 0.02 / 0.41 / — ms |
| 2 フレーム以内に出た（見積もり） | 100 % | 100 % |
| 鍵 → 音（DAC に届く予定）平均 / p95 / 最大 | 13.22 / 15.68 / 15.96 ms | 13.5 / 15.8 / 16.0 ms |

- 最初に測ったときは、鍵 → 画面の p95 が約 12〜14 ms で、**悪くなっていた**。理由: 窓いっぱいの WebGL の面を、計器が流れている間 60 Hz で出していて、WebKitGTK の主スレッドがふさがり、鍵の知らせが後ろで待っていた。面を描く場所ごとの小さな canvas に分け、変わったときだけ描く形に直した（`docs/architecture.md` 7 章）。直す前と後の表は `docs/measurements/`。
- 検証との差（p95 で 0.3 ms ほど）は、WebKitGTK の `performance.now()` が 1 ms 刻みで、時計合わせに ±0.5 ms のずれがあるため、この方法では見分けられない大きさ。
- 鍵 → 音の最初の区間（鍵盤の中と USB）と、画面に光が出た瞬間は、ソフトでは測れない（検証と同じ限り）。
- 今回の鍵は仮想の鍵盤（`meloet-vkeys`）。本物の鍵盤での数は、まだ取っていない。

### 次の回への申し送り（第 2 回: 録って、聞く）

- 再生まわりのボタン（⏮ ▶ ■ ● ループ）、メトロノーム、カウントインは、今は「使えない」状態で置いてある。中身を入れるときは `Transport.svelte` と、core の意図（`Command`）を足す。
- 曲のデータ（`meloet-model`）には、まだ保存（serde）も取り消しもない。`TempoChange` の中身は仮の形。
- 録音の文面（「録音待機」「録った音がならびます」など、モックにだけある物）は ja.ts に入っているが、今回は出していない。録音が本当になったら出す。
- 「音が出ました」の案内は、仕様書の文のまま「赤い丸の録音ボタンを押すと…」と言っている。録音ボタンが使えるようになれば本当になる。
- 鍵 → 音は、音が鳴っていない間の鍵を音のスレッドに送らない。録音では、音がひらいていない間の鍵をどう扱うか決める。
- ピアノの音源は次の回より後（第 4 回の「最初から入っている音色」）でもよいが、音源の口（`Instrument`）はもうある。サンプルの読みこみは音のスレッドの外で。

### この PC で気づいたこと

- PipeWire の `clock.force-quantum` は、いま **256**（検証の報告書を書いた時点は 1024 だった）。棟梁も係も変えていない。だから「バッファが固定」の文面は、本物ではまだ出ていない（偽物の場面と、テストで確かめた）。
- GPU が 2 枚あり、HDMI の出口が 7 つ見える（どれもノードがなく、えらべない）。
