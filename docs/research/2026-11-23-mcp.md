# MCP for the AI link (research, 2026-11-23)

Research by meloet-research (Sonnet 5.5) for round 10, item 13 (the AI link). Every source was read on 2026-11-23. Confidence: A = primary source, B = secondary source that cites a primary one, C = unknown source or our own inference.

## Conclusions

1. **The MCP spec is now version `2026-07-28`** (A; the one before is `2025-11-25`). It is stateless: no `initialize` handshake, every request carries the protocol version and client capabilities in `_meta`, and a server MUST implement `server/discover`. The stdio transport (one JSON-RPC message per line, nothing but MCP on stdout, logs on stderr) did not change. A custom transport over a reliable byte stream (a Unix socket) SHOULD use the same line format.
2. **The official Rust SDK is `rmcp`** (A): 3.11.0 (2026-11-17), Apache-2.0 (the repository is moving from MIT to Apache-2.0; both fit meloet's MIT OR Apache-2.0), MSRV 1.88, edition 2024, Tier 1 in the MCP SDK list. It implements `2026-07-28` and stays compatible with older versions. It needs tokio. Features of interest: `server`, `macros` (`#[tool]`), `schemars`, `transport-io` (stdio), `transport-async-rw` (any `AsyncRead + AsyncWrite` pair). Versions move fast (3.0 broke things); pin the version (C).
3. **Not sure yet** (C): whether `serve(stdio())` in rmcp 3.11 speaks the new `server/discover` or only the old `initialize`. Claude Code falls back to the old handshake when discovery fails, so it should connect either way, but this must be tried before building on it (a small spike).
4. **Registering a local stdio server** (A): Claude Code: `claude mcp add --transport stdio --scope user meloet -- /usr/bin/meloet-mcp` (scopes local / project `.mcp.json` / user). Claude Desktop has an official Linux beta (Debian and Ubuntu); its config file `~/.config/Claude/claude_desktop_config.json` (`{"mcpServers": {...}}`) is described only in the MCP docs (B).
5. **Audio in tool results** (inference from A): MCP allows `audio` content, but the Claude Messages API `tool_result` has no audio type (text, image, document, search_result …). Claude is not expected to hear audio. Return numbers (loudness, peaks) as text or `structuredContent`; a picture (PNG) of a waveform or levels can be seen.
6. **Safety** (A): the host must get the user's consent before tool calls; a server must check inputs, control access and limit calls; tool annotations are only hints, and their defaults lean to the unsafe side (`destructiveHint` true, `openWorldHint` true), so set `readOnlyHint: true` and `openWorldHint: false` where they apply (C). Local servers should use stdio, or a Unix socket with narrow permissions.
7. **Unix socket** (A): put it under `$XDG_RUNTIME_DIR` (owned by the user, mode 0700, gone at logout); on Linux, connecting needs write permission on the socket file, so make it 0600 (umask 0177 before `bind`, or `chmod`); read the peer's uid with `SO_PEERCRED`; `sun_path` is 108 bytes; do not use abstract sockets (no permissions); unlink a stale socket only after checking that nobody answers on it.

## Details worth keeping

- Changes in `2026-07-28` (A): sessions and `Mcp-Session-Id` removed (state goes in handles passed as tool arguments); `ping` and `logging/setLevel` removed; results need `resultType` (`complete`, `input_required`, `task`); servers no longer send requests (elicitation and sampling use "input_required" results and a resend); tasks moved to the extension `io.modelcontextprotocol/tasks`; `tools/list` needs `ttlMs` and `cacheScope` and should keep a stable order; JSON Schema 2020-12 is allowed in `inputSchema` and `outputSchema`.
- Tools are model-controlled, resources application-driven, prompts user-controlled (A). Reading and writing notes fits tools.
- Errors (A): unknown tool or broken request → JSON-RPC error; a failed run → result with `isError: true` and a text the model can act on. Tool names: 1–128 characters of `A-Za-z0-9_-.`.
- Progress and cancellation (A): progress only when the client sends `_meta.progressToken`, values must grow; on `notifications/cancelled` the server should stop and not answer. Long work: plain `tools/call` with progress, or the tasks extension (Claude Code supports tasks from v2.1.304 in public beta and moves a main tool call over 2 minutes to the background by itself).
- Claude Code limits (A): output over 25,000 tokens (`MAX_MCP_OUTPUT_TOKENS`) is cut, text over 50,000 characters is saved to a file; images (PNG, JPEG, GIF, WebP) are shown in the conversation.
