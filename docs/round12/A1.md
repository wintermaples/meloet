# A1: repeat clips (a handle and a command)

## Architecture

What goes into chapter 25 of `docs/architecture.md`.

- **Model** (`meloet_model::arrange::repeat_clips(doc, clips, count)`): the clips given (those not there are left out, one given twice counts once, as `duplicate_clips`) are one block from the earliest start to the latest end; copy `k` (1..=count) of each clip goes `k × (block length)` later on its own track. Everything goes through `place`, the same as move, copy, duplicate and paste: new ids from `Doc::next_id` in the order copy 1 (the clips in the order given), copy 2, …; the takes are shared (`Arc`), so a later note edit makes a new take only in the clip edited; name, shown take and (for audio) the fades, volume and pitch go with the copy. Lanes live on the track, so nothing of the automation is copied. All or nothing: `Overlap` when any copy would overlap a clip on its track (only the copies themselves count, not the block's span: a clip lying in a gap between two copies is not in the way), `OffTheSong` when the last copy would end past `MAX_TICK` (checked first with `checked_mul`, so a huge count never allocates). `count` 0 is `Unchanged`; the model has no upper limit of its own. Step `StepKind::RepeatClips { count }` where `count` is the number of clips made (clips × copies), so the history row says how many clips came.
- **Positions are ticks**: a copy follows on at exactly `start + k × length` whatever meter or tempo changes lie under it; a length that is not a whole number of bars stays as it is (spec).
- **Core** (`Play::repeat_clips`, next to `duplicate_clips`; `state.rs` takes `Command::RepeatClips`): refused while busy (count-in, recording) and outside `1..=REPEAT_COUNT_MAX`; `OffTheSong` is turned into `Overlap` so that the song's end gives the same notice as a clip in the way (the protocol's doc says so). Then `apply_placed` as Mod D: the copies are selected; the clip clicked last gets its first copy clicked and shown in the piano roll; the notice is `StatusMessage::ClipsNotDuplicated`. Undo brings back the selection before (the originals).
- **Screen: the handle** (`arrangeDrag.ts`): `clipHit` takes an optional `RepeatGrip` (width, smallest clip) and returns `repeat: true` on the right end of the name strip (`repeatGripBox`: `space.3` wide but at most a third of the clip; the height of the strip, `line.mark` + the `text.s` line; no handle on a clip narrower than `part.take.tag-min-width`). The handle comes before the edges, so in the name strip the right edge is the handle and under it the length is as before. Callers without a grip (old tests) get no handle.
- **Hit order with audio clips**: `AudioClipHandles.svelte` takes a press on a fade handle in the capture phase on `.lanes` and stops it, so the lanes never see it. The fade-out handle sits 2 px into the bottom of the name strip at the right end, inside the repeat handle; `Arrange.svelte`'s `hitAt` drops `repeat` on a fade handle box (`fadeHandleBox`), so the cursor and the ⟳ do not promise a repeat there. Trap for tests: a `pointerdown` sent to `.lanes` itself reaches both the capture and the bubble listeners of that element (stopPropagation does not stop listeners on the same node); send it to a child (`.lanes > .fill`) as the real pointer does.
- **Screen: the drag** (a third `ClipDrag` kind, `repeat`): the group is the selection when the pressed clip is in it (else the pressed clip alone, after `selectClip`), as for a move. `room` (how many copies fit before a clip in the way, up to `REPEAT_COUNT_MAX`; `repeatRoom`) is worked out once at the first move. The count is the pointer's move in ticks over the block length, rounded to the nearest whole number, put into `0..room`. Release sends one `repeatClips` when the count is 1 or more; a plain press only selects; Esc (`cancelDrag`) drops it.
- **The picture**: the clips stay as they are on the big face (`dragKey` is empty for a repeat, so the big face is not drawn again). The copies are drawn in the existing small slot (`recordingClip` region, `.drag-clip`) in a box the full visible width of the group's rows, so a new count changes only the rectangles, not the box (`G.paintRepeats`: for each copy a `gray.2` face and a `gray.7` border, then a `line.mark` accent bar at the end of the last copy on the held clip's row, where the handle is). No new WebGL region. The reading in place and the status line say 「{n} 回くり返します」 (from the mock); nothing with 0 copies.
- **⟳**: one small HTML element in `.labels` (`repeat-mark`), only while the pointer is on a handle or the handle is held; it changes only when the pointer crosses a handle, never at 60 Hz.
- **The box of 「くり返す…」**: `ui/src/components/arrange/repeatBox.svelte.ts` holds which clips (and which clip it sits on); `Arrange.svelte` draws it like the clip name box: an HTML `<input>` at the end of the block (x of the latest end, kept inside the visible width), on the name strip of the right-clicked clip, else of the upper clip that ends last. It opens with `REPEAT_COUNT_DEFAULT` (3) chosen and focused. Enter sends one `repeatClips` (a whole number is put into 1..99; anything else gets the broken border and Enter does nothing), Esc or a press outside (blur) closes without sending, ↑ ↓ step by 1 (10 with Shift). While it is open the status line says 「{n} 回くり返します」 through `dragReading.text` (cleared when it closes). It closes when recording or the count-in starts, when its clips are gone, and when the arrange folds into the overview.
- **Keys and menus**: `KeyAction { kind: "repeatClips" }` for Mod R (also while typing, as Mod D and Mod J; in `WITH_MOD`, so the browser's default is always prevented). `runKeyAction` opens the box (screen only, nothing is sent); `keyActionUsable` uses `repeatTarget` (`clipEdits.ts`: the chosen clips, not while busy, not in the overview). The row 「くり返す…」 comes right after 「複製」 in 「編集」 and in the clip's right-click menu. The key list row moved from `WAVE2_ROWS` to `ACTION_ROWS.repeatClips`.
- **Mod R and reloading**: wry 0.57.2 (`src/webkitgtk/`) binds no key to reload, and `meloet-app` has no accelerators; the keydown's default is prevented anyway, so WebKitGTK treats the key as handled by the page.
- **Fake** (`ui/src/bridge/fake.ts` `reduceClips`): `repeatClips` places the copies with `place` (all or nothing, `clipsNotDuplicated`). Its selection follows the fake's `place` (the last copy of the clicked clip), not core's first copy.

## Spec rules

For `docs/spec/3-bands.md`, "Rules added in round 12":

- A clip has a repeat handle at the right end of its name strip: as wide as `space.3` but at most a third of the clip, as high as the name strip. Under the name strip the right end is still the length. A clip narrower than 28 (`part.take.tag-min-width`, the width under which the take tag gives way to the square) has no handle; it can still be repeated with the menu or Mod R. On an audio clip, the fade handle comes first where the two meet.
- The pointer on the handle shows ⟳ (accent) there and the copy cursor.
- Dragging the handle right adds frames of whole copies (a `gray.2` face with a `gray.7` border; an accent bar at the right end of the last one), the nearest whole number of clip lengths; it stops before the next clip in the way, and at 99. The clips stay as they are. The reading in place and the status line say 「3 回くり返します」. Release: one step 「クリップをくり返す」; Esc puts it back; no copy, nothing.
- With several clips chosen, the handle of any of them repeats them all as one block (the earliest start to the latest end), each clip on its own track.
- 「くり返す…」 (Mod R) in 「編集」 and in a clip's right-click menu, right after 「複製」: a box of digits at the end of the chosen clips, 3 at first and chosen. Enter makes the copies (a number outside 1–99 becomes the nearest end; what is not a whole number cannot be decided), Esc or a press outside closes it, ↑ ↓ change it by 1 (10 with Shift). While it is open the status line says 「3 回くり返します」. Disabled with no clip chosen, while counting in or recording, and while the arrange is only the overview.
- A count that would put a copy over a clip, or past the song's end: nothing, and 「ほかのクリップと重なるので、複製できませんでした。」.
- After repeating, the copies are chosen; the clip clicked last gets its first copy clicked and shown in the piano roll (as Mod D). Undo takes all the copies away in one step and chooses the originals again.
- `docs/spec/4-keys.md`: a row "Repeat the chosen clips (a box of digits)" | <kbd>Mod</kbd> <kbd>R</kbd> | <kbd>Mod</kbd> <kbd>R</kbd> | Works.
- Step name 「クリップをくり返す」 is already in the list of round 12 (wave 2); its row says the clips made.

## Readings

- **The mark ⟳ shows only while the pointer is on the handle** (and while it is held), not whenever the pointer is over the clip: the spec's sentence 「マウスが乗ると印（⟳）が出ます」 is in the handle's item. If the owner wants it on every clip under the pointer, only `repeatHover` in `Arrange.svelte` changes.
- **"The name strip does not show"** is read as "the clip is narrower than `part.take.tag-min-width` (28)", the width where the name strip already gives way to the take square. The handle's width is `space.3` (12 at 100 %), the named value equal to the spec's 「幅 12 px」.
- **The copy cursor** on the handle and during the drag (the OS shapes are `move`, `copy`, `ew-resize`, `not-allowed`; a repeat makes copies). `not-allowed` when no copy fits at all.
- **The count of a drag is rounded to the nearest whole copy**, so a copy appears once the pointer passes half of it ("whole copies only" holds: nothing in between is ever made).
- **The frames of the copies** are a `gray.2` face with a `gray.7` border (the drag rule's border, and the mock's dark face), with a `line.mark` accent bar at the end of the last copy (the mock's right border). The mock's dashed top in the track color is not drawn (the text says 「写しの枠」, frames); the clips themselves are not framed, since they do not move.
- **The notice** for a count that would overlap is the existing 「ほかのクリップと重なるので、複製できませんでした。」 (`clipsNotDuplicated`), the closest of the three overlap notices; past the song's end gives the same.
- **Where the box sits**: at the end of the block, on the name strip of the right-clicked clip, else of the upper clip that ends last; kept inside the visible width. It is a text box of two digits in the look of the clip name box, not the 24-high input of the parameters.
- **A typed count out of 1..99** is put into the range without a notice (B-68's "nearest end"), because `ValueField` has no field for it (see the report). Full-width digits are read.
- **Mod R also works while typing** (as Mod D and Mod J), so the browser never gets the key.
- **In the overview** (the arrange folded to its upper band) 「くり返す…」 and Mod R are disabled: the box needs the clips on screen.
- **A double click on the handle** opens the name box, as anywhere on the name strip.
- **After a repeat**, what is chosen follows Mod D (`apply_placed`): all copies, and the first copy of the clip clicked last is clicked and shown in the piano roll.
- Wording made here (`ui/src/text/ja.ts`): `menu.repeatClips` 「くり返す…」, `arrange.repeatMark` 「⟳」 and `arrange.readRepeat` 「{count} 回くり返します」 (all three from the spec, `user:2026-11-23`); `arrange.repeatCount` 「くり返す回数」 (the box's label for screen readers, `builder:2026-11-23`).
- New pictures (no mock boards): `arrangeRepeatHover`, `arrangeRepeatDrag`, `arrangeRepeatBox`, `arrangeRepeated` in `tools/design/shoot_ui.py` (clicks on the scene `arrangeTrimmed`, 1280×800 at 100 %), shot in the six themes. `menuClip` now shows the new row.

## User documents

- `README.md` (English), feature list: "Repeat clips: drag the handle at the right end of a clip's name, or use 「くり返す…」 (Ctrl R) and type how many times. The copies follow right after, as one undo step; several chosen clips repeat as one block."
- `README.ja.md` and `docs/user/README.ja.md`: 「クリップをくり返す：クリップの名前の右端の持ち手を右へ引くか、「くり返す…」（Ctrl R）で回数を打ちます。写しはすぐ後ろに続き、1 回で取り消せます。いくつか選んでいれば、ひとかたまりでくり返します。」
