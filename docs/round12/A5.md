# A5 Recently opened songs

## Architecture

- The list was already kept by `crates/meloet-core/src/recent.rs` (`recent-songs.json`, 20 paths, newest first). Its file format is unchanged. The core holds it in `Files::recent` (`state/songs.rs`).
- Ids: `Files::recent_ids` runs beside `Files::recent`. A path keeps its id while it stays in the list (also when it moves to the top); a new path gets the next number from `last_recent_id`, and numbers are never given again in one run. So an id the screen sent from an older list names the same song, or nothing (a song that left the list, or a cleared list). Ids start from 1 at each start of meloet; they are not saved.
- View: `Model::recent_view` gives the newest `RECENT_SHOWN` (10) rows: `name` is the file name without `.meloet`, `place` is the folder shown with `plugins::shown_path` (home as `~`) and a final `/`. The absolute path never leaves Rust.
- `Command::OpenRecent { id }` goes the way of a file the PC hands over (`Then::OpenGiven`): refused unless `song_free()` (not recording or counting in, no save or window waiting, no dialog up); asks first about unsaved changes (the same Unsaved dialog as 「ひらく…」); then reads the file without the PC's open window.
- A song that does not read: the existing Broken dialog (「読めない」). When the reason is that the file is gone (`!path.exists()` at the time the read failed), the path leaves the list and the list is written (`Effect::SaveRecentSongs`). A file that is there but broken stays in the list. This check is in the `SongUnreadable` arm, so it also covers a handed file or an AI-link read of a path in the list.
- `Command::ClearRecent` empties the list and writes it (only when it was not empty). The AI link's `list_songs` sees the empty list too.
- Screen: `ListRow.detail` (new optional field in `menus.ts`) is thin text after the name (`.m-lbl`, gray.8), drawn by `MenuList.svelte`. The sub list is built by `recentRows` in `menus.ts`.

## Spec rules

- File menu: 「最近ひらいた曲 ▸」 right under 「ひらく…」. Inside: up to 10 songs, newest first: the song's name, and its folder in thin text (`~/…/`). After a separator, 「一覧を消す」. With no songs: only a disabled row 「まだありません」 (no separator, no 「一覧を消す」).
- A song row is usable exactly when 「ひらく…」 is (not while recording or counting in). 「一覧を消す」 is always usable. The parent row is always usable (so 「まだありません」 can be seen).
- Pressing a song row opens it as 「ひらく…」 does with the file already picked (the unsaved-changes question first). The song open now: nothing happens.
- A song file that is gone: the 「読めない」 dialog, and the song leaves the list.
- Not a step; not part of the song. No key.

## Readings

- 「曲の名前」 is read as the song file's name without `.meloet` (the name inside the file would need reading every file). Normally the same, as a song's file is named after the song.
- 「場所」 is the folder that holds the file, written like other places (`~` for home) with a final `/` (as the example in `RecentSong::place`).
- Choosing the song that is open now does nothing (the same as a file the PC hands over for the open song). It does not reload the file.
- A gone file is found when the read fails, not before asking about unsaved changes. So with unsaved changes the person is first asked, then told it does not read; the song open now is kept either way.
- A file that exists but does not read stays in the list (the spec says only "なくなっていたら").
- 「一覧を消す」 can be used while recording (it does not touch the song).
- Wording (all `user:2026-11-23`, from the spec): 「最近ひらいた曲」 `menu.recentSongs`, 「一覧を消す」 `menu.clearRecent`, 「まだありません」 `menu.noRecent`. No wording was made up.
