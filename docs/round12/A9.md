# A9: reverse and normalize audio clips (round 12)

## Architecture

What goes into chapter 25 of `docs/architecture.md`.

- **The frames a clip plays** (`meloet_model::played_frames`, `crates/meloet-model/src/audio/reverse.rs`): of the shown take, the file frame at the clip's start (`from`) and at its end (`to`), and where the take or the file ends (`audio_end`). The clip is silent below frame 0 and from `audio_end` on; frames between 0 and the take's `first_frame` do sound, as in the read-ahead thread. Each tick is rounded to a frame by itself, as `pcm::feed_clip` does (rounding the difference instead put the length one frame off now and then, and then "reverse twice" was not the same audio). A clip that follows the song's tempo counts in the take's own tempo map; one that does not, in the song's. Two `PlayedFrames` are equal only when the clip plays the same frames of the same file of the same take; that is how a late answer is checked.
- **Both need the file, so both go to the keeper thread** (`audiofiles/keeper.rs`, new asks `Measure` and `Reverse`, news `AudioNews::Measured` and `AudioNews::Reversed`; the work itself in `audiofiles/clips.rs`). The core thread does not read files (22-18 A2). The keeper does an ask in one go, as `Bring` already does with a whole copy; a long clip keeps the keeper busy for that time.
- **Normalize does not use the peaks file.** Its finest level is not exact enough: a peak covers 256 frames, so at each end of the clip it holds frames the clip does not play (after a cut, the loud part just past the cut counted), and the i16 values stop at full scale, so a float file louder than 0 dBFS reads as 0 dBFS. The keeper reads the frames instead: a plain wav where it is (`WavPcm`), anything else decoded from its head (`Decoder`). The volume is `−1.0 − 20 log10(peak)` dB, put into −60..+12 and rounded to 0.01 dB (`meloet_model::normalize_gain`).
- **Reverse writes a new file in the work place** and never touches the file the clip plays. The new file holds the clip's frames backwards: `R[i] = S[to − 1 − i]` for `i` in `0 .. to − max(from, 0)`, silence where `S` has no audio (past `audio_end`). So silence at the clip's end becomes silence at the new file's head; silence before the file's frame 0 at the clip's head is past the new file's end, where the new take is silent anyway.
  - A plain wav (any kind `WavPcm` reads: 8, 16, 24, 32-bit integer, 32 and 64-bit float) is reversed frame by frame as bytes, reading the source backwards in blocks of 32768 frames: the new file has the same kind of samples, so reversing twice gives the same bytes. Unsigned 8-bit silence is 128. Anything else (mp3, ogg, flac) is first decoded into a temporary float wav in the work place (a decoder only goes forwards), which is then reversed the same way and removed; the new file is 32-bit float.
  - The file is written under a temporary name, synced, then given its name with a hard link (it cannot take a name a recording got at the same moment; a plain rename where links do not work), and the folder is synced. Its peaks are made while it is written and kept under a fresh uid; then `AudioStore::file_arrived`.
  - Name: `vocalrec::file_name(track, id)` as A7 asks, with the ids the step will give (guessed; nothing depends on it), and " 2", " 3" … when a file of the song's places or a name of the audio table has it.
- **One step when the answer comes** (`play/reverse.rs`, `state/audio.rs` `ask_clip_work`). The command is refused while busy; the answer is held while a recording counts in or runs and goes in when it ends (as imports). A clip whose `PlayedFrames` are not the same any more (deleted, another take shown, trimmed, moved to where the tempo differs, the step already in) is passed over; an answer for another song (`Play::serial`) is dropped. A clip that already waits for an answer is left out of the next ask: otherwise the second answer would find a new take and do nothing without a word.
- **The reverse step** (`meloet_model::reverse_clips`): each file goes into the audio table (`sha256: None`, as recordings), and the clip's shown take is replaced, at the same index, by a new take (new id) that plays the file from frame 0 with its tick 0 at the clip's start (`offset` 0). The other takes, the fades, the volume, the pitch stay. Mirror placement holds for clips that follow and for clips that do not.
- **Tempo of the backwards audio** (spec: 「曲のテンポについていく」): if the take has a tempo and it is one tempo all along the clip (`tempo_piece` over the clip's take ticks, cut at 0), the new take gets that tempo (`SourceTempo::steady`) and the switch stays. If the tempo changes along the clip, the new take has no tempo and the switch is turned off; a clip that was following is counted for `ReverseFollowOff`. A take without a tempo keeps the switch as it is.
- **Undo**: both are plain steps of the `Doc`; undo puts the old take (and the old audio table) back. The new file stays in the work place (redo needs it) and moves to `音/` at a save only while a take uses it (`songfile::used_audio`). Files made for answers that were dropped stay in the work place until it is emptied. Song file and recovery file: no change of shape.
- **Fake** (`ui/src/bridge/fakeA9.ts`): answers at once from the made-up peaks over the take's frames; a backwards file is a `FakeAudio` with `backwardsOf`, whose peaks are the source's the other way round.
- **Traps**: `chunks_exact` with a constant size is a clippy error now (`as_chunks`). `History` keeps `next_id` growing across undo, so ids are not given twice; the check by value is still what decides.

## Spec rules

For `docs/spec/3-bands.md`, "Rules added in round 12":

- 「逆にする」 and 「ノーマライズ」 at the bottom of an audio clip's right-click menu (after a line) can be used now; while counting in or recording they are disabled. They act on the selected clips; keys clips among them are passed over, and so are audio clips whose file is not found. Several clips: each one, all in one step.
- 「ノーマライズ」: no new file. The clip volume is set so that the loudest sample of the frames the shown take plays in the clip (from the clip's start to its end) is −1.0 dBFS, within −60..+12 dB. A clip that cannot reach it stops at the end of the range and the status line says so; a silent clip is left as it is and the status line says so. Fades and pitch are not counted. One step 「ノーマライズ」.
- 「逆にする」: a new file of the frames the clip plays, backwards (what was silent at the clip's end is silent at its head), in the work place; the shown take is replaced by a new take of it in the same place, from the clip's start. Other takes, fades and volume stay. Again: another new file (back is undo). One step 「逆にする」, made when the file is ready (the files are made in the background; nothing is shown meanwhile).
- A clip that follows the song's tempo, whose audio has one tempo along the clip, keeps following with that tempo. If the tempo changes along the clip, the clip stops following and the status line says so. The clip's length does not change.
- A clip that is still waiting for its file or its measurement is passed over by the next 「逆にする」 or 「ノーマライズ」.
- Step names: 「ノーマライズ」 and 「逆にする」 are already in the list of round 12.
- No keys (spec 4 unchanged).

## Readings

- Wording made here (source `builder:2026-11-23`, `ui/src/text/ja.ts`; shown on the status line, `StatusLine.svelte`):
  - `msg.normalizeLimited`: 「{count} つのクリップは、いちばん大きい音を −1.0 dB にできませんでした（クリップの音量は −60 〜 +12 dB まで）。」
  - `msg.normalizeSilent`: 「{count} つのクリップは音がないので、そのままにしました。」
  - `msg.reverseFollowOff`: 「{count} つのクリップは、もとの音のテンポが途中で変わるので、「曲のテンポについていく」をオフにしました。」
  - Source `builder:` (developers' text where the spec has none). If the lead prefers `user:2026-11-23` (spec 1-3 lets helpers make such lines), change the three tags.
- When one normalize has both silent and limited clips, the status line says the silent one (nothing was done to those).
- "The range used by the shown take" is read as the frames the clip plays from its start to its end (not the whole take): a clip cut or trimmed is measured and reversed only where it sounds.
- Normalize measures the file's samples, not what pitch, stretch or fades make of them.
- A take with a tempo that changes along the clip, on a clip that does not follow: its backwards take has no tempo (「この音のテンポ」 shows 「—」), as there is no one tempo to keep. The spec only speaks of clips that follow.
- The rows are usable whenever the song may change; they are not disabled for a clip whose file is missing (Rust passes such clips over without a word). Normalize of a file that cannot be read, or a reverse whose file cannot be written (disk full), does nothing and says nothing (stderr only): the spec has no text for it.
- A file brought in from mp3, ogg or flac is reversed into a 32-bit float wav; a wav keeps its own kind of samples.
- New pictures: scene `audioNormalized` (the right clip at +12.0 dB with `msg.normalizeLimited`), and click shot `menuAudioClip` (the menu of 「歌 テイク 1」 in `audioEdit`) in `tools/design/shoot_ui.py`; no mock boards for them.

## Left for later

- No progress and no way to stop a long 「逆にする」 (the spec asks for none). The keeper thread does one ask at a time, so an import or a 「さがす…」 waits behind a long reverse or measurement (the same is already true behind `Bring`).
- No message when the file cannot be read or written (a missing shape: a `StatusMessage` such as "could not make the file"; needs wording from the owner).
- A8 (comping) will make "the frames the shown take plays" differ from what is heard; decide with A8 how a clip with comp pieces is reversed or normalized (refuse, or work on what is heard).
- When the backwards file's rate is not the engine's (a 44.1 kHz file in a 48 kHz song), the clip shows 「読みこんでいます」 for a moment after the step, while the keeper makes its cache, as for any such file.
- Normalize of an mp3, ogg or flac decodes from the file's head each time.
- An open AI batch and an answer that comes during it: the step is made as an import's is; not checked against the batch rules.
- Not checked by hand in the real app (no window was opened); `menuAudioClip` and `audioNormalized` were shot from the fake in six themes.
