# D1 — the in-app notice of a new version

The apt repository half of D1 is in `scripts/make-apt-repo.sh` and `docs/development/apt-repo.md` (done before); this note is only about the in-app half.

## Architecture

- `crates/meloet-core/src/updates.rs`: the look itself. `Options { url, stamp_dir, https_only, timeout, current }`, `check(&Options, now_ms) -> Option<String>` (blocking), `spawn(options, tell)` (one thread, `meloet-updates`, per look). The same HTTP crate and style as the sound pack's fetch (`ureq` 3.5.2, rustls with the PC's certificates, Mozilla's when the PC has none, `http_status_as_error(false)`), with `timeout_global(5 s)` for the whole read (name lookup to the end of the body) and an answer limit of 1 MiB. Only `GET` with `Host` and `User-Agent: meloet/<version>`: the agent's `Accept` is set to `""` so ureq sends none, and without the gzip/brotli features ureq sends no `Accept-Encoding` (a test checks the server saw exactly `host` and `user-agent`). Any failure (no net, timeout, not 200, broken JSON, no `tag_name`, a tag that is not three numbers) is `None` and nothing is said.
- Versions are compared by our own `Version(u64, u64, u64)`: `vX.Y.Z` or `X.Y.Z`, exactly three numbers; anything else (`v0.4.0-rc1`, `nightly`) is not a version. Shown without the `v` ("0.4.0").
- Once a day: `update-check.json` beside `settings.json` (in `settings::config_dir()`, so `MELOET_CONFIG_DIR` moves it too) holds `{ checkedMs, latest }`. It is written before the read, so a read that fails or hangs also counts for the day; after a good read `latest` is the version found (newer or not). Within 24 hours of `checkedMs` nothing goes out and `latest` is compared again with this meloet (so a new start the same day still says it, and says nothing once the person has put the new version in). A stamp that does not parse, or a `checkedMs` in the future (clock put back), counts as no stamp.
- The release page is a Rust constant built from the version: `https://github.com/wintermaples/meloet/releases/tag/v<version>`. The screen never sends an address.
- Development hooks: with the `dev-hooks` feature, `Options::from_env` gives `None` unless `MELOET_UPDATE_URL` is set; then it reads that URL (`http://` allowed) and keeps no stamp (a test server's answer must never be kept and then shown by the release build within the day). Without the feature, the real URL. The release binary has no `MELOET_UPDATE_URL` string (checked with `strings` on a debug build without the feature); `scripts/check-release.sh` lists `MELOET_UPDATE_URL` in `rust_must`.
- `CoreOptions::updates: Option<updates::Options>` (`from_env` fills it, `offline()` is `None`, so tests never go out). The core thread: `Effect::CheckUpdates` starts `updates::spawn`, whose answer comes back as `Msg::NewVersion` → `Input::NewVersion(String)`. `Effect::OpenUrl(String)` becomes `ShellRequest::OpenUrl` (the shell's `pcwindow::open_url`, https only, was already there).
- `crates/meloet-core/src/state/updates.rs` (`UpdatesSide`): the look goes out at most once a run, after `Input::ScreenUp`, only while `check_updates` is on; turning the switch on later in the run (after the greeting) sends it then. The status line message `StatusMessage::NewVersion` is shown only while the song is not moving (`!play.is_moving()`: not while playing, in the count-in or recording); it waits until stopped. It goes away for the run with 「あとで」 (`DismissNewVersion`), 「ページをひらく」 (`OpenReleasePage`), or when the song moves after the status line said it (`settle_updates` after every input). `UpdatesView::new_version` stays for 「meloet について」.
- Place in the status line's order: after the screen's own and the core's notices, before the lasting keyboard lines (「鍵盤をさがしています」, the chooser) — it is the only one with a 「あとで」, so it does not hide them for long.
- Trap met: two worktrees sharing one `CARGO_TARGET_DIR` ran the other tree's test binary (the warning in CLAUDE.md is real). After `cargo clean -p` of the workspace crates the right binary ran.

## Spec rules

For `docs/spec/3-bands.md` "Rules added in round 12" (user:2026-11-23):

- 「新しい版をたしかめる」: after the screen's greeting, at most once a day, meloet reads the newest release of GitHub. It sends only `User-Agent: meloet/<version>`, gives up after 5 s, and says nothing when it fails. The day of the last read is kept beside the settings, not in the song.
- When the tag (`vX.Y.Z`) is newer than this meloet, the status line says 「新しい版 0.4.0 があります」 with 「ページをひらく」 (the release page in the PC's browser) and 「あとで」, only while stopped (not while playing, in the count-in or recording; it waits until stopped). At most once a run: 「あとで」, 「ページをひらく」 or starting the song after it was said puts it away until the next start.
- 「meloet について」 has the line 「新しい版 0.4.0 があります」 under the version while a newer version was found (all the run, also after 「あとで」).
- The advanced sound settings have the row 「新しい版をたしかめる」 (on at first) after 「AI とつなぐ」. Off: meloet never goes out, and what was found is no longer shown.
- No key, no step name, no menu row.

## Readings

- 「止まっているとき」 is read as "the song is not moving" (`is_moving()` false), so playing also waits, not only the count-in and recording.
- 「同じ版は、起動ごとに1回まで」 is read as: the notice stays while stopped until 「あとで」 or 「ページをひらく」, or until the song is started after the status line showed it. It does not come back in the same run.
- Once a day = 24 hours since the last read (as the sound pack's catalog look, `CHECK_EVERY`), not the calendar day.
- Turning 「新しい版をたしかめる」 off also takes away what was found (status line and 「meloet について」); an answer that comes while it is off is dropped. Turning it on again later in the same run looks once (if the look has not gone out yet in this run).
- With the development hooks nothing is remembered (no stamp), so a test server's version is never kept.
- The status line order: before 「鍵盤をさがしています」 and the keyboard/chooser lines (else a person without a keyboard plugged in would never see it), after every notice.
- 「meloet について」: the line sits in the facts block under 「バージョン」, in the value column with an empty label, text colour gray.10 (`.strong`), no button (the spec asks for one line only).
- Wording made up in the style of the neighbours (source `user:2026-11-23`, in `ui/src/text/ja.ts`): `settings.checkUpdatesOn` 「オン」 and `settings.checkUpdatesOff` 「オフ」 (the same words and choice mark as 「AI とつなぐ」). `button.newVersionLater` 「あとで」 is the spec's word; the existing `button.packLater` is the same text but kept apart (other source).
- At 100 % the name 「新しい版をたしかめる」 just fills the 120 name column of the advanced settings (no gap is lost, nothing is cut); see the scene `checkUpdatesOff`.

## User documents

- `README.md` (English): "Tells you when a new version of meloet is out (once a day at most, only the version is asked; can be turned off in the sound settings)."
- `README.ja.md` and `docs/user/README.ja.md`: 「新しい版が出ると、止まっているときにステータスラインでお知らせします（1日に1回まで。送るのは meloet の版だけ。音の設定の「新しい版をたしかめる」で切れます）。入れるのは手で（deb を落として入れるか apt）。」

## Measurements

None. Nothing runs on the audio thread or at 60 Hz. Nothing to measure for speed; the read is on its own thread, at most once a day.
