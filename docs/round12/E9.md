# E9 「書き出しました」, the dialog when an export ends (round 12)

Spec: `docs/history/round12-spec.ja.html` E9 (lines 430-446). Protocol 31 shapes were already in; no shape was added.

## Architecture

- **Core holds the dialog.** The dialog is open while `ExportView::run` is `ExportRunView::Done`; there is no other flag. A finished run was already "shown until the person does the next thing" (`Exporting::saw_command` clears an ended run on any command except a few). So the dialog closes the same way: 「閉じる」, Esc and Enter send `Command::CloseExport` (with no export dialog open it does nothing else; `saw_command` takes the run away). Any other command the person sends (play, a click in the arrange…) also closes it, as it puts away the status line's 「書き出しました」 today. No screen-only state module was needed (unlike 「meloet について」), so a reconnect shows the same thing.
- **The trap of `saw_command`.** `Command::PlayExported` is added to the commands that keep the run (with `ShowExported`, `SetViewport`, `Audition…`); otherwise the dialog would close the moment 「PC のプレーヤーで聞く」 is pressed.
- **The waveform.** `export/wave.rs` `WaveBars`: `convert()` (`export/job.rs`) feeds it every chunk it reads, after F1's gain and before the sample-rate conversion, the dither and the writing; the file is cut into `EXPORT_WAVE_BARS` (200) parts of the same number of frames, each the largest absolute sample of both channels, `round(min(|s|, 1) · 255)`. Samples that are not finite count as 0. Taken before the rate conversion: the shape is the same, and the frame count is known up front. It goes to the rules in `ExportNews::Finished { wave }` (core-only shape) and from there into `Done::wave`.
- **「トラックごと」 has an empty `wave`**, whatever the number of files (even a song of one track). The screen uses `wave.length === 0` to know it is 「トラックごと」 (name 「N つのファイル」, no waveform, no loudness, 「PC のプレーヤーで聞く」 off), and core refuses `PlayExported` the same way (`Exporting::played`). The protocol comment says "Empty for several files"; the lead may want to make it "Empty for 「トラックごと」" at the next shape commit.
- **Opening the file.** `PlayExported` → `Exporting::played()` (the one file of a `Done` run with a waveform) → `Effect::OpenFile(path)` (new, next to `Effect::OpenUrl`) → `ShellRequest::OpenFile` → `pcwindow::open_file` (`xdg-open`, on its own thread).
- **Not shown** for a cancelled or failed run (they are not `Done`; the status line says them as before) nor for the AI link's exports: `ai_render` sends its news to its own channel and never sets `Exporting::run` (read in `service.rs` `ai_render` / `export_ask`).
- **Screen.** `ui/src/components/export/ExportedDialog.svelte` (copy of the About / key-list dialog frame: `movableDialog`, `data-dialog-head`), mounted in `App.svelte` while `state.export.run?.state === "done"`. Text functions in `ui/src/components/export/exported.ts`. The waveform is one SVG `<path>` (200 bars, `preserveAspectRatio="none"`, centred on the middle line as the mock), `fill: color.meter.ok` on `color.meter.ground`. Esc and plain Enter in `ui/src/keys/attach.ts` send `closeExport`; the undo-history band does not take Esc while the dialog is open.
- **For F2 (mp3).** The line 「3 分 12 秒 ・ 48000 Hz ・ 24 ビット」 is made only in `exportedDetails()` of `ui/src/components/export/exported.ts`. For an mp3, add the case there (the format is not in `Done` today: F2 needs a field such as the format or the bitrate in `ExportRunView::Done`, and a wording entry next to `exported.details`).

## Spec rules

For `docs/spec/3-bands.md` "Rules added in round 12":

- When an export ends, the dialog 「書き出しました」 opens: the file's name (text.m), 「3 分 12 秒 ・ 48000 Hz ・ 24 ビット」, the waveform (200 bars, meter.ok on meter.ground), 「大きさ −14.0 LUFS ・ トゥルーピーク −1.0 dBTP」 (the file as written, after 「公開先に合わせる」), and the place. Buttons: 「PC のプレーヤーで聞く」 (opens the file with the PC's own app), 「フォルダをひらく」, 「閉じる」 (bright, Enter). The heading has 「閉じる Esc」.
- 「トラックごと」: the name is 「5 つのファイル」 (the real count), no waveform and no loudness line, 「PC のプレーヤーで聞く」 cannot be pressed.
- Not shown when the export was cancelled or failed, nor for the AI link's exports; the status line says those as before.
- The status line's 「… を書き出しました（…）。」 with 「フォルダをひらく」 stays under the dialog. Closing the dialog, or doing anything else, puts both away.
- Keys (`4-keys.md`): Esc and Enter close 「書き出しました」.
- No step names (the song does not change).

## Readings

- Wording from the spec (`user:2026-11-23`, `ui/src/text/ja.ts`): `exported.title` 「書き出しました」, `exported.files` 「{count} つのファイル」, `exported.length` 「{minutes} 分 {seconds} 秒」 and `exported.details` 「{length} ・ {rate} Hz ・ {bits} ビット」 (from the mock's 「3 分 12 秒 ・ 48000 Hz ・ 24 ビット」), `exported.loudness` 「大きさ {lufs} LUFS ・ トゥルーピーク {peak} dBTP」 (mock), `exported.play` 「PC のプレーヤーで聞く」. 「フォルダをひらく」, 「閉じる」, 「Esc」, 「Enter」 are the existing `button.openFolder`, `button.close`, `key.esc`, `key.enter`.
- Wording made up (`builder:2026-11-23`): `exported.lengthSeconds` 「{seconds} 秒」 for a file under a minute (instead of 「0 分 45 秒」).
- Numbers: one decimal with U+2212, a true peak above 0 with 「+」 (as F1). A loudness not measured but a true peak there: 「−∞ LUFS」. Both not there (silence): no loudness line. Seconds are cut off, as the status line's 「3:02」.
- The waveform's height is `size.overview` (40 at 100 %): the mock's 36 is not a named value. The bars are centred vertically (the mock's `align-items:center`). The dialog is `part.dialog.width` (560) like the other dialogs; the mock's 420 is a picture width.
- The dialog's text sizes and gaps: body padding space.3 / space.4 (as the other dialogs' rows), the waveform and the loudness line space.2 below what is above them (the mock's 8 px).
- 「閉じる」 is the bright (primary) button with 「Enter」 after it, as the mock.
- How the dialog closes (core holds it; `CloseExport`; any other command closes it too) is my decision, see Architecture. If the lead wants it to stay open while the person plays, core needs a "dialog closed" state and the status line's run must outlive it (a shape change).
