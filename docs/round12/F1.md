# F1 「音の大きさ」 of the export (round 12)

Spec: `docs/history/round12-spec.ja.html` F1 (lines 714-736). Protocol 31 shapes were already in; no shape was added.

## Architecture

- **Where the numbers come from.** The dialog's job (one file: not 「トラックごと」, not the AI link's measuring) now hears what it renders twice besides the file, on the export's job thread (`export/job.rs`, `Taker`):
  - the loudness: the same `analysis::Listener` the AI link uses (ITU-R BS.1770-4, gated), fed only the range (`Taker::take`), so the tail is not in it. `Listener::lufs_now` gives the loudness so far for the check while counting.
  - the true peak: `export/loudness.rs` `TruePeak`, a thin wrapper of `ebur128` 0.1.11 with `Mode::TRUE_PEAK` only (4× oversampling below 96 kHz, 2× below 192 kHz), fed in `Taker::write`, so the tail is in it. The louder channel, `20·log10`.
  - Both go to the rules in `ExportNews::Counted` (`lufs`, `true_peak_db`, a few times a second; the last one with `done` has the values of the whole file). A job for each track, and the AI link's measuring jobs, send `None`.
- **The gain.** `export/loudness.rs` `match_gain(lufs, true_peak)`: `gain = −14 − lufs`, but at most `−1 − true_peak` (limited), and it turns down as well. `None` when the loudness is not measured or is below −70 LUFS. The same function decides the line of the dialog (`ExportDialogView::loudness_result`), the gain the job puts on the file, and the loudness and true peak of `ExportRunView::Done` (the measured values plus the gain; filled for E9, `wave` left to E9).
- **Where the gain goes.** `ExportTarget` (core only) has `loudness`. 「書き出す」 sends `Match` only when it can be used now. The job decides the gain itself, once the target has come and the file is rendered, from its own final numbers (「書き出す」 can be pressed while the check still counts). It is put on every sample in `convert()`, after reading the rendered float file and before the sample-rate conversion, the dither and the writing. Without a gain `convert()` does exactly what it did: 「そのまま」 is bit-identical to before.
- **The rules** (`export.rs`): `Exporting::loudness` is the choice, kept as long as meloet runs (as the format). `can_match`: not for 「トラックごと」; for a job that is done, only when `match_gain` gives a gain; before the job is done it is not known, so it can be chosen (a song near silence becomes unusable when the check ends). The view's `loudness` is what will happen (`AsIs` while it cannot be matched), so the screen needs no rule. `ExportChange::Loudness { Match }` while it cannot be matched does nothing. With 「公開先に合わせる」 in force the check's `clips` is false: the file ends at −1 dBTP or lower, nothing in it goes over 0 dB (the clipping lines, 「このまま書き出す」 and the status line's 「0 dB をこえる所があります」 go away).
- **ebur128 and flush-to-zero (a trap).** `ebur128` 0.1.11 `Filter::process` (src/filter.rs, `ftz::with_ftz`) sets FTZ in MXCSR while it filters and restores the old value afterwards (always, on x86_64). Chapter 19-2 says meloet does not set FTZ/DAZ (the Rust docs call it undefined behaviour). It happens only on the export's job thread, only inside the crate's own call, never on the audio thread. Contained: `TruePeak::feed` is `#[inline(never)]`, so no float work of the export's engine can be moved into that stretch; a test (`the_true_peak_leaves_the_threads_float_settings_as_they_were`) checks that denormals are kept after a feed. Fable (asked during the work) judged it acceptable with that containment. If the lead does not accept it, the way out is our own BS.1770 Annex 2 interpolator (48 taps, 4 phases), a small piece of code.
- `ebur128` gets `opt-level = 3` in the dev profile (root `Cargo.toml`), as the other audio crates, so that a debug build's check does not slow down.
- A sample that is not finite is given to the true-peak meter as 0 (one bad sample would stay in its filter for good).
- The AI link: its measuring jobs are as before; its render jobs (one file) now also measure loudness and true peak (a little CPU, nothing changes in what they write: their target is always `AsIs`).

## Spec rules

For `docs/spec/3-bands.md` "Rules added in round 12", the export dialog (34-B):

- A row 「音の大きさ」 under 「形」: 「そのまま」 (at first) and 「公開先に合わせる」, and on the right 「−14 LUFS ・ −1 dBTP」.
- 「公開先に合わせる」 puts one gain on the whole file (the tail too): −14 minus the measured loudness, but only until the true peak reaches −1 dBTP. It turns down too. No limiter.
- The loudness is measured over the range only (not the tail); the true peak over the whole file (the tail too).
- 「公開先に合わせる」 cannot be chosen for 「トラックごと」 (those files are for mixing later), nor for a song whose loudness cannot be measured or is below −70 LUFS (known once the check is done). While it cannot be chosen, 「そのまま」 is shown on and the file is written as it is; the choice is kept and comes back when it can be used again.
- The choice is kept for as long as meloet runs, as 「形」 is.
- 「書き出す前のたしかめ」: after the peak line (and its clipping lines), 「曲ぜんたいの大きさ −18.6 LUFS ・ トゥルーピーク −3.2 dBTP」; while counting 「ここまでの大きさ −18.6 LUFS ・ トゥルーピーク −3.2 dBTP」 (a loudness not known yet is 「—」). No such line for 「トラックごと」 nor for silence.
- With 「公開先に合わせる」, once the check is done, one more line: 「合わせると 4.6 dB 大きくなります」, 「合わせると 2.4 dB 小さくなります」, or at the true-peak limit 「−1 dBTP を越えないよう、−15.2 LUFS になります」.
- With 「公開先に合わせる」 the file does not clip: no clipping lines, the button is 「書き出す」.
- The AI link's export tool always writes as it plays.
- No keys, no step names (nothing of the song changes).

## Measurements

None (the PC was not quiet). For the lead after the merge:
- `tools/measure/export_app.py same`: 「そのまま」 must stay the same as the output's sound (the code path of `convert()` without a gain is unchanged).
- `tools/measure/export_app.py speed`: the check now runs the K-weighting and the 4× true-peak filter on the job thread for every one-file job; compare with the numbers before.

Tests (all pass): fixed signals (1 kHz sines, quiet, loud, quiet with short peaks) matched and measured again with ebur128 alone: −14.0 LUFS ±0.2, or −1.0 dBTP ±0.2 when limited; at 44100 and 96000 Hz ±0.3. The song of the export's tests rendered, matched and measured again: at −14 ±0.2 or at −1 dBTP ±0.2. Our BS.1770 loudness agrees with ebur128's within 0.05 LU on the quiet sine and on the range of the test song.
