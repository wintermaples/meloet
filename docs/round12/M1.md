# M1 Presets of the built-in effects

## Architecture

- **Factory presets** (「はじめから入っているもの」) are one table in `crates/meloet-model/src/presets.rs` (`factory(kind)`, one `const` array per effect, each preset an `id` and `(parameter name, value)` pairs). `cargo test -p meloet-protocol` writes them to `ui/src/bridge/generated/presets.ts` (`FACTORY_PRESETS`, every parameter's value in the order of `EFFECT_PARAMS`). The screen names them `preset.<effect>.<id>` in `ja.ts`. Gate, de-esser and saturation have an empty list for now (M6 adds two each).
- `presets::left_as_is(kind)`: a factory preset of the **reverb or the delay does not change its mix**. The mix depends on the strip (`Insert::new_on`: 100 % on a return, `INSERT_MIX` 30 % on a track or the master), and the table cannot know where the insert is. Applying skips it; recognising "the preset the values are" ignores it. The generated TS still has the default mix (100) at that place, because the shape asks for every parameter; the fake skips it the same way.
- **User presets** (「自分で残したもの」) belong to the PC: `crates/meloet-core/src/presets.rs`, file `presets.json` in `settings::config_dir()`, written like the settings (whole temporary file, synced, renamed). Shape, version 1:
  `{"version": 1, "effects": {"compressor": [{"name": "いつもの", "params": {"threshold": -18.0, "ratio": 3.0, …}}]}}`.
  `params` is the same shape as `InsertFile.params` of the song file (a number, a step's name, or a switch as `true`/`false`); the two helpers `songfile::param_file` / `param_value` are shared by both now.
  Reading: a missing, broken or other-version file is no presets. A broken entry, an entry with no name (after trimming), a name already read, or one past 100 is left out. A parameter this meloet does not know is skipped; a value out of range is brought into range; a parameter that is missing is simply not in the preset (it stays as the insert has it when used). An effect name this meloet does not know is kept as raw JSON and written back unchanged.
- In memory: `UserPresets` (one list per `EffectKind::ALL`) lives in `Play` (`user_presets`), so `params_view` can compute `SelectedInsert::preset`. It is loaded once at start (`Model::with_user_presets`, from `service.rs`) and written with the new core effect `Effect::SavePresets(Box<UserPresets>)` (handled in `service.rs` next to `SaveSettings`). `AppState::presets` is `UserPresets::view()` (only kinds that have any, in `EffectKind::ALL` order; names in the order they were first kept).
- **Applying** (`play/presets.rs`, `Play::apply_preset`): refused while `busy()`; nothing for a slot without a built-in effect, a preset id the effect does not have, or a user name not there. Parameters whose lane **moves** (`Lane::moves()`: not resting and has points) are left out and counted. The rest go through `Play::effect_params_edit` — the loop that was inside `ai_set_effect_params`, now shared (the AI link still refuses when a lane exists; the preset skips). The edit's step is replaced by `StepKind::ApplyPreset { strip, slot, kind }`, so it is one step 「プリセットを使う」 and undo brings every value back. The engine gets the values through the usual mixer sync, so they move over 20 ms like any parameter change. When something was left, `StatusMessage::PresetLanesKept { count }` (said even when nothing else changed).
- **The name on 「プリセット ▾」** (`Play::preset_of`): the first factory preset of the effect whose values (all but `left_as_is`) equal the insert's, else the first user preset whose kept values all equal the insert's. Values are compared with a tiny tolerance (`1e-6` relative) so a value that went through JSON still matches.
- **Keeping** (`Play::save_preset`): the name is trimmed and cut to 40 characters (`presets::name_of`); empty → nothing. All the insert's values are kept. The same name is written over in its place (`PresetOverwritten`); a new name past 100 for that effect is refused (`TooManyPresets`, nothing written). Not a step; allowed while recording (it does not touch the song). **Removing** (`DeletePreset`): not a step; nothing if the name is not there.
- Screen: `ui/src/components/params/BuiltinList.svelte` has a row above the list with the button (right side, `on` in the accent when the values are a preset; text 「プリセット ▾」 or 「<name> ▾」). It opens `PresetMenu.svelte` as the first thing inside the list's scroll area (so 100 user presets scroll with the list). The menu keeps its own keys (Esc, Enter) and stops them, because the list around it uses ↑ ↓ and Enter. `presetName.ts` gives a preset's shown name.
- Fake: `ui/src/bridge/fakePresets.ts` (applying, keeping, removing, and the preset name, as Rust; the user values live in a module map for as long as the page lives). Hooked into `reduce` of `fake.ts` after the mixer. Scenes `presets` and `presetsNone`; `shoot_ui.py` shoots `presets`, `presetsMenu`, `presetsSaving`, `presetsNone`.
- Traps: the stub test `the_commands_of_round_12_wave_2_are_taken_and_change_nothing_yet` (core) and its TS twin listed the three M1 intents; they are taken out of both now. `UserPresets` implements `Default` by hand (nine empty lists), so equality does not depend on whether a list was touched.

## Spec rules

- At the head of the parameter list of a built-in effect (between the search box and the list), on the right, a button: the name of the preset whose values the insert has now (in the accent, 「<name> ▾」), otherwise 「プリセット ▾」. Not for plugins, not for instruments.
- The button opens a list in place (gray.5 frame on gray.2): 「はじめから入っているもの」 and its rows, 「自分で残したもの」 and its rows, then 「いまの設定を残す…」 (accent). The row of the preset the values are has gray.3 behind it. A heading with no rows still shows (the gate, de-esser and saturation have no factory presets yet).
- A row uses the preset and closes the list: one step 「プリセットを使う」 (step name already in the list). Not while counting in or recording (the rows are disabled). A parameter a lane moves (not resting) stays, and the status line says 「レーンが動かしている N つのパラメータは、そのままにしました」.
- A factory preset of the reverb or the delay leaves the mix as it is (it depends on whether the insert is on a return, or on a track or the master).
- 「いまの設定を残す…」 turns into a name box in its place (40 characters at most). Enter keeps (spaces at the ends are dropped; an empty name keeps nothing) and closes the list; Esc puts the row back; Esc again closes the list. The same name is written over: 「「<name>」を上書きしました」. 100 per kind of effect: past that, 「<effect>のプリセットは 100 個までなので、これ以上残せません。」 and nothing is kept. Not a step; works while recording.
- Right click on a row of 「自分で残したもの」: a menu with 「消す」. Not a step.
- 「自分で残したもの」 are kept on the PC (`presets.json` next to the settings), not in the song.
- No new key.

## Readings

- The spec says the factory table goes into architecture; per the round's brief it is in this note (table above) for the document helper.
- Reverb and delay presets do not set the mix (see Architecture). User presets do set every kept value, the mix too (the person kept them in a place they chose). **Question for the lead/owner:** should user presets also leave the reverb/delay mix alone?
- The button row: the mock shows the effect name on the left of the button; the panel already shows the name above, so the row holds only the button on the right.
- The list is drawn in the panel (as the mock), not as a floating menu, and scrolls with the parameter list.
- Factory ids (camelCase) were chosen here: `eq4` vocalClear, unmuddy, cleanLows, fatBass; `compressor` vocalEven, drumPunch, bassSolid, gentleGlue; `reverb` smallRoom, hall, behindVocal; `delay` echo, slapback, pingPong; `chorus` subtleWide, deepSwirl; `limiter` finish, gentle.
- The menu order is the spec's text order (the mock lists the compressor's in another order; the text wins).
- User presets are listed in the order they were first kept; writing over keeps the place.
- A name longer than 40 characters is cut to 40 (the box does not let more in anyway; JS counts UTF-16 units, Rust counts characters).
- 「プリセット ▾」 is `on` (accent) whenever the values are a preset (the mock shows it so).
- ApplyPreset is refused while counting in or recording (the common rule for song changes), though the mixer's own parameter moves work while recording.
- Wording made up (`builder:2026-11-24`, in `ui/src/text/ja.ts`):
  - `preset.named` 「{name} ▾」 — the button with a preset's name.
  - `msg.presetOverwritten` 「「{name}」を上書きしました」.
  - `msg.presetLanesKept` 「レーンが動かしている {count} つのパラメータは、そのままにしました」.
  - `msg.tooManyPresets` 「{effect}のプリセットは {max} 個までなので、これ以上残せません。」 (after `msg.tooManyTracks`).
- Wording from the spec (`user:2026-11-23`): 「プリセット ▾」, 「はじめから入っているもの」, 「自分で残したもの」, 「いまの設定を残す…」, 「消す」, and the 18 preset names.
