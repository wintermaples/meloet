# P3 Velocity and length tools

## Architecture

- Model: `crates/meloet-model/src/notes/bulk.rs` (a child module of `notes`, so it uses the private `pick`, `lifted`, `put_notes`). `change_picked` is the indexed form of `change_each`: the closure gets every picked note at once, with its index in the take, so a tool can look at the other picked notes (the ramp's first and last start, legato's next start) and at the index (the random number). The new take goes in place through `put_notes`, as every other note edit; the picked notes stay marked, so the selection stays.
- `scale_velocity`: `round(v × percent / 100)` as `(v × p + 50) / 100` in integers (half up), then 1..=127. `percent` is put into 10..=300 in the model and in core.
- `ramp_velocity`: from `from` at the earliest picked start to `to` at the latest, by start, rounded half away from zero in integers (`i128`), then 1..=127. All at one start: `from`.
- `random_velocity`: `splitmix64((seed << 32) ^ index) % (2n + 1) − n` added, then 1..=127 (`random_delta`, `splitmix64`). The index is the note's index in the shown take (the one the intent names), so a note gets the same number whether picked alone or with others. A small bias from `%` is accepted. The first numbers for seed 1 are pinned in a test.
- `legato`: the picked starts sorted and deduped; each picked note ends at the first picked start after its own. Not-picked notes are neither changed nor a "next" start. Notes of the latest start stay. The length is at least 1 since the next start is later.
- No change: `EditError::Unchanged` from `put_take_reaching`, as before (no step).
- Core: `crates/meloet-core/src/play/bulk.rs` (`impl Play`): `scale_velocity`, `ramp_velocity`, `random_velocity`, `legato`, one helper `bulk_notes` that does what `match_velocity` does: refused while `busy()` and for an old take id (`aimed`), the notice is said also when nothing changed (as `VelocityMatched` is), no notice when the command does nothing (old take, no or bad indexes).
- Screen: `ui/src/components/pianoroll/bulkTools.ts` (ranges, reading, ↑↓, the intents), rows in `NoteInspector.svelte`. The seed is made by the screen on each press (`Math.random`). `fake.ts` only says the notice, as for `matchVelocity`.
- Trap: the ramp row has two input boxes in the width of one (`mock.inspector.bulk-field`); with the usual padding "110" did not fit, so those two boxes have no padding and centred text.

## Spec rules

- 「ベロシティをまとめて変える」, when opened, has under 「ベロシティ」 the rows 「割合」 (box, %, 「かける」; 10–300, first 100), 「だんだん」 (two boxes with →, 「かける」; 1–127 each, first 40 and 110), 「ばらつき」 (±, box, 「かける」; 1–32, first 8). 「長さをそろえる」 has under 「長さ」 the row 「次の音までのばす」 with 「のばす」. Each acts on the selected notes as one step; with nothing selected they are 「使えない」. Enter in a box presses its 「かける」; Esc puts back the value last used; ↑ ↓ by 1, with Shift by 10. The selection stays.
- Maths as in the round-12 spec P3 (see Architecture for the rounding).
- Step names (already in): 「ベロシティを割合で変える」 `scaleVelocity`, 「ベロシティをだんだん変える」 `rampVelocity`, 「ベロシティをばらつかせる」 `randomVelocity`, 「次の音までのばす」 `legato`.
- No new keys.

## Readings

- The first values of 「だんだん」 are 40 and 110 (the spec's picture; the text gives none).
- Out-of-range numbers are put at the nearest end. For the two velocity boxes of 「だんだん」 the status line says so (`ClampValue`, field velocity) and an unreadable one says `RejectValue` with the value last used, as the other velocity boxes. For 「割合」 and 「ばらつき」 there is no `ValueField`, so the value is put at the end without words, and an unreadable one only turns the box red (nothing is sent). (A `ValueField` for them would be a protocol change; left to the lead.)
- The box values are kept while the panel is shown (they are tool settings, not of the selection); not saved.
- The notices are said also when no note changed (as 「そろえる」 does), but no step is made.
- Wording made up (source `builder:2026-11-23`, `ui/src/text/ja.ts`):
  - `msg.velocityScaled` 「{count} ノートのベロシティに {percent} % をかけました。」
  - `msg.velocityRamped` 「{count} ノートのベロシティを {from} から {to} へだんだん変えました。」
  - `msg.velocityRandomized` 「{count} ノートのベロシティを ± {amount} でばらつかせました。」
  - `msg.notesLegato` 「{count} ノートを次の音までのばしました。」
- Wording from the spec (`user:2026-11-23`): 割合, だんだん, ばらつき, かける, 次の音までのばす, のばす; the marks %, →, ± are those of the spec's picture.
